# Morrow 前端视觉重构设计

## 目标

将当前技术 Demo 风格的单页界面改造成名为 **Morrow** 的生活方式百货，同时保留 Mini-RecSys 的推荐诊断能力。页面默认服务商品浏览，诊断信息在桌面端常驻右侧，在移动端收进抽屉。

本次只修改 `frontend/`，不改变后端 API、推荐算法、反馈事件语义或数据结构。

## 用户与核心任务

- 普通使用者：选择用户、搜索商品、获取个性化推荐，并对推荐执行 Like 或 Dismiss。
- 推荐系统开发者：观察响应时间、过滤数量、召回来源、推荐原因及各项排序分数。
- 页面单一主任务：浏览个性化商品，同时解释当前选中商品为何被推荐。

## 视觉方向

采用已确认的 **Quiet Department** 方向。

### 色彩

- `Mist`: `#EEF1F2`，页面背景。
- `Paper`: `#F9FAF9`，商品与控件表面。
- `Graphite`: `#283136`，主文字和诊断区基色。
- `Berry`: `#9B3F4D`，品牌、主操作和当前商品信号线。
- `Cool Green`: `#66806F`，成功状态、Like 和低干扰强调。
- `Blue Gray`: `#CAD3D6`，边界与媒体占位。

页面不使用渐变、玻璃拟态、发光、装饰色球或大面积单色卡片。圆角限制在 `0-6px`，阴影只用于移动端抽屉和必要的悬浮层。

### 字体

- 品牌和少量栏目标题：`Georgia`, `Times New Roman`, serif。
- 商品、导航、按钮和说明：`Aptos`, `Segoe UI`, sans-serif。
- 响应时间和评分：`Cascadia Code`, `Consolas`, monospace。

使用系统字体避免增加外部字体网络依赖。字号使用固定的响应式层级，不随视口宽度连续缩放。

### 标志性元素

当前商品卡显示一条莓红信号线和明确的选中状态，右侧诊断栏同步显示该商品的来源、原因和分数。这是页面唯一的强调动效，建立商品与推荐解释之间的直接关系。

## 信息架构

### 桌面端

1. 顶部导航：Morrow 品牌、品类入口、搜索入口和当前用户选择。
2. 内容标题区：当前模式、用户或搜索词、结果数量、响应时间。
3. 主内容区：约 `minmax(0, 2.2fr) + 360px`。
4. 左侧商品网格：推荐或搜索结果。
5. 右侧诊断栏：吸顶、独立页面分栏，不包在装饰卡片中。

### 移动端

1. 导航压缩为品牌、搜索按钮和用户选择。
2. 商品网格根据宽度使用单列或双列。
3. 诊断栏改为底部抽屉，通过固定的图表图标按钮打开。
4. 抽屉支持关闭按钮、遮罩点击关闭和 `Escape` 关闭。

## 组件边界

- `App`: 保存请求状态和页面模式，编排 API 调用。
- `ShopHeader`: 品牌、品类导航、搜索和用户选择。
- `ResultsHeader`: 当前上下文、结果数量、响应时间和重新推荐操作。
- `ProductGrid`: 只负责结果布局和空状态。
- `ProductCard`: 展示商品、价格、分类、Like/Dismiss，并发送选中事件。
- `RecommendationInspector`: 展示服务状态、过滤数量、来源、原因和完整评分。
- `MobileInspectorSheet`: 复用相同诊断内容，只处理移动端抽屉交互。
- `Notice`: 统一错误和操作状态。

组件拆分以职责为界，不引入新的全局状态库。

## 数据流与能力保留

### 推荐模式

1. 用户选择保持使用 `GET /users` 的结果。
2. 点击推荐调用 `GET /recommend?uid=<id>`。
3. 保存用户、推荐结果、过滤数量和响应时间。
4. 继续为返回结果逐项发送 `impression` 事件。
5. 默认选择第一件商品用于诊断；点击或键盘聚焦其他商品时更新诊断栏。
6. Like/Dismiss 继续调用 `POST /events`，成功后刷新推荐。

### 搜索模式

1. 提交非空关键词调用 `GET /search?q=<query>`。
2. 商品网格切换为搜索结果，不展示 Like/Dismiss。
3. 诊断栏切换为搜索上下文，展示查询词、响应时间和当前商品可用字段；缺失的推荐评分显示 `Not available`，不伪造数据。

### 状态行为

- 初始状态：展示简洁的浏览引导，不展示空诊断数字。
- 加载状态：按钮和反馈操作禁用，商品区域使用稳定尺寸的骨架占位，避免布局跳动。
- 错误状态：在结果标题区下方显示具体错误，并保留可再次执行的入口。
- 图片失败：显示带商品首字母的中性占位，不影响卡片尺寸。
- 空结果：说明当前条件没有结果，并提供返回推荐模式的动作。

## 交互与可访问性

- 图标使用 `lucide-react`，搜索、刷新、心形、关闭、图表等操作使用熟悉图标，并提供 `aria-label` 和 tooltip。
- 商品卡可通过键盘聚焦和选择；Like/Dismiss 是独立按钮，不依赖卡片点击。
- 所有交互具有清晰的 `:focus-visible` 状态。
- 色彩不是状态的唯一表达方式；选中、错误和禁用状态同时使用文字或图标。
- 尊重 `prefers-reduced-motion`，关闭抽屉和选中状态的过渡动画。

## 响应式约束

- 页面最大内容宽度约 `1440px`，保留稳定侧栏宽度。
- 商品网格在桌面端根据可用空间使用 2-3 列，在平板和移动端使用 1-2 列。
- 商品图使用稳定 `4 / 3` 宽高比；标题固定两行高度，动态内容不会推动按钮和价格位置。
- 所有按钮和输入框允许文字换行或使用合理最小宽度，避免窄屏重叠。

## 验证方案

- 运行 `npm run build`，确认生产构建成功。
- 使用真实浏览器验证推荐、搜索、用户切换、Like/Dismiss、曝光上报和错误状态。
- 分别检查约 `1440x900`、`1024x768` 和 `390x844` 视口。
- 截图检查商品、导航、诊断栏和移动端抽屉没有重叠、裁切或不可读文字。
- 检查键盘焦点、`Escape` 关闭抽屉、图片失败占位和 reduced-motion 行为。

## 非目标

- 不新增购物车、结算、登录或收藏业务。
- 不改动后端接口和推荐算法。
- 不增加新的前端状态管理框架。
- 不将算法分数直接铺满每张商品卡。
