# 推荐系统中的特征交叉与常见交叉模型

## 1. 什么是特征交叉

推荐系统中的原始特征，通常可以分为三类：

- **用户特征**：年龄、城市、兴趣标签、消费水平、历史行为等；
- **物品特征**：类别、作者、价格、时长、发布时间等；
- **场景特征**：时间、设备、网络、地理位置、推荐入口等。

单个特征主要描述某个对象自身的属性，例如：

```text
用户喜欢游戏
视频属于游戏类别
当前时间是晚上
```

但推荐系统真正需要判断的是：

> 当前这个物品，在当前场景下，是否适合当前用户？

因此，仅观察单个特征通常不够，还需要建模多个特征之间的关系。例如：

```text
用户兴趣 × 视频类别
用户消费水平 × 商品价格
当前时间 × 视频时长
用户城市 × 商家城市
```

这种由多个原始特征共同构造关系信息的过程，就叫做**特征交叉（Feature Crossing）**。

可以用一句话概括：

> **单个特征描述“对象是什么”，特征交叉描述“对象之间是什么关系”。**

---

## 2. 为什么排序模型需要特征交叉

假设模型中有两个二值特征：

```text
x1：用户是否喜欢游戏
x2：当前视频是否属于游戏
```

只使用线性模型时，模型大致只能学习：

```text
用户喜欢游戏，增加多少分；
视频属于游戏，增加多少分。
```

但真正重要的业务关系可能是：

```text
只有当用户喜欢游戏，并且视频也是游戏时，
这个组合才会显著提高点击概率。
```

这意味着模型不仅需要学习 `x1` 和 `x2` 各自的作用，还要学习：

```text
x1 × x2
```

即“用户兴趣与物品类别是否匹配”。

在工业推荐系统中，特征交叉主要用于表达以下关系：

1. **用户与物品的匹配关系**
   - 用户兴趣 × 内容类别；
   - 用户品牌偏好 × 商品品牌；
   - 用户消费水平 × 商品价格。

2. **用户与场景的匹配关系**
   - 用户作息 × 当前时间；
   - 用户设备习惯 × 当前设备；
   - 用户网络偏好 × 当前网络环境。

3. **物品与场景的匹配关系**
   - 视频时长 × 当前时间；
   - 视频清晰度 × 当前网络；
   - 商品类别 × 当前季节。

---

## 3. 特征交叉不只是简单乘法

工程上的特征交叉，本质是利用多个原始特征构造新的关系特征，不一定只是两个数相乘。

常见形式包括：

```text
相等判断：
用户城市 == 商家城市

差值：
商品价格 - 用户历史平均消费价格

比值：
商品价格 / 用户平均消费价格

集合重合：
用户兴趣标签 ∩ 视频标签

向量内积：
user_embedding · item_embedding

向量拼接：
concat(user_embedding, item_embedding)
```

例如：

```cpp
struct CrossFeature {
    bool category_match;
    bool city_match;
    double price_gap;
};

CrossFeature build_cross_feature(
    const UserFeature& user,
    const ItemFeature& item) {

    return {
        .category_match =
            user.favorite_category == item.category_id,

        .city_match =
            user.city_id == item.city_id,

        .price_gap =
            item.price - user.avg_price
    };
}
```

这些交叉特征比原始的“用户城市”“商品城市”“用户均价”“商品价格”更直接地表达用户与物品之间的关系。

# 4. 四类常见模型的整体定位

本文重点介绍以下四类方法：

- FM：因式分解机；
- DCN：深度交叉网络；
- LHUC / PPNet：个性化门控网络；
- SENet + Bilinear：特征选择与双线性交互。

它们关注的问题并不完全相同：

| 模型 | 主要解决的问题 | 直观理解 |
|---|---|---|
| FM | 稀疏特征的二阶交叉 | 让所有特征两两握手 |
| DCN | 显式高阶特征交叉 | 让特征逐层组队 |
| LHUC / PPNet | 用户级、场景级个性化 | 为不同用户调节神经元音量 |
| SENet + Bilinear | 动态特征选择与精细二阶交互 | 先挑重点，再精细交叉 |

需要注意：

> **PPNet严格来说不是传统的特征交叉模型。**

FM、DCN和Bilinear主要回答：

```text
特征之间应该如何交互？
```

而PPNet主要回答：

```text
对于当前用户或当前场景，
网络中的哪些隐藏单元应该更加重要？
```

因此，PPNet通常可以与FM、DCN等交叉模块组合使用。

# 5. FM：低成本的二阶特征交叉

## 5.1 核心思想

FM会为每个特征学习一个较短的隐向量，然后通过两个隐向量的内积，表示两个特征之间的交互强度。

例如：

```text
用户喜欢游戏     → 向量 A
视频属于游戏类别 → 向量 B

A · B 较大
    ↓
说明该用户和该视频比较匹配
```

可以将FM类比为：

> 每个特征都携带一张“性格卡片”，两个特征见面后，通过比较性格卡片判断它们是否合适。

## 5.2 基本结构

```text
原始稀疏特征
      ↓
为每个特征查找Embedding
      ↓
所有有效特征两两做内积
      ↓
汇总一次项和二阶交叉项
      ↓
输出预测分数
```

## 5.3 FM解决了什么问题

如果直接为每一种特征组合保存独立参数，例如：

```text
用户城市=上海 × 视频类别=游戏
用户城市=北京 × 视频类别=游戏
用户城市=广州 × 视频类别=游戏
```

特征组合数量会非常庞大，而且很多组合在训练数据中出现次数很少。

FM使用Embedding共享参数，使低频组合也可以借助单个特征学到的向量进行泛化。

## 5.4 适用场景

FM适合以下情况：

- 类别特征非常多；
- 输入特征高度稀疏；
- 主要关心二阶交叉；
- 在线推理延迟要求较高；
- 需要简单、稳定的排序基线。

常见于：

- 广告CTR预估；
- 推荐粗排；
- 轻量级精排模型；
- Wide & Deep、DeepFM等模型的交叉部分。

## 5.5 优点

- 结构简单；
- 适合大规模稀疏特征；
- 参数共享能力强；
- 比人工枚举交叉特征更容易泛化；
- 推理成本相对较低；
- 工业上较稳定，容易作为基线。

## 5.6 缺点

- 原始FM主要表达二阶交叉；
- 所有特征对的交互形式比较统一；
- 难以直接表达复杂的高阶关系；
- 不会主动判断哪些特征更重要；
- 对不同用户缺少显式个性化调节能力。

## 5.7 一句话记忆

> **FM：让所有特征以较低成本两两认识。**

# 6. DCN：逐层构造显式高阶交叉

DCN全称为 **Deep & Cross Network**。

## 6.1 核心思想

真实推荐规律通常不仅包含两个特征，还可能包含多个特征的共同作用：

```text
年轻用户
× 晚上
× Wi-Fi环境
× 长视频
```

普通FM主要建模二阶交叉，而DCN通过多层Cross Layer，让原始特征在每一层继续参与组合。

可以粗略理解为：

```text
第1层：形成较低阶交叉；
第2层：在前一层基础上继续组合；
第3层：形成更复杂的高阶关系。
```

不需要深究具体公式，只需记住：

> Cross层的职责是有组织地构造显式交叉关系。

## 6.2 基本结构

```text
稀疏特征 → Embedding ┐
数值特征 → 归一化    ├→ 拼接得到 x0
                     │
          ┌──────────┴──────────┐
          ↓                     ↓
     Cross Network          Deep Network
     显式特征交叉            隐式非线性学习
          ↓                     ↓
          └──────────┬──────────┘
                     ↓
                   拼接
                     ↓
                 预测输出
```

两条分支分别承担不同职责：

- **Cross Network**：有规律地构造显式交叉；
- **Deep Network**：使用MLP学习复杂、隐式的非线性关系。

## 6.3 类比理解

可以把Cross Network理解为做菜时逐层加入原始食材：

```text
原始食材：鸡肉、辣椒、盐、糖

第一层：鸡肉 × 辣椒
第二层：鸡肉 × 辣椒 × 糖
第三层：鸡肉 × 辣椒 × 糖 × 盐
```

它不像普通MLP那样完全自由地混合，而是让原始输入持续参与后续组合。

## 6.4 适用场景

DCN适合：

- 用户、物品和场景特征较多；
- 二阶交叉不足以表达业务规律；
- 希望自动学习高阶交叉；
- 不希望完全依赖人工特征工程；
- 精排阶段需要更强的表达能力。

常见于：

- 推荐精排；
- 广告CTR/CVR预估；
- 搜索排序；
- 多任务排序网络的底层共享模块。

## 6.5 优点

- 能自动学习显式高阶交叉；
- 交叉结构比普通MLP更有针对性；
- 可以与DNN并行，兼顾显式和隐式关系；
- 减少人工枚举高阶组合特征的工作量；
- 比单纯增加MLP宽度或深度更直接地建模交叉。

## 6.6 缺点

- 结构和推理成本高于FM；
- Cross层数需要调优；
- 层数太浅表达能力不足，太深可能增加训练难度；
- 输入维度较大时，计算和参数成本会上升；
- 虽然叫显式交叉，但具体学到的业务规则仍不一定直观。

## 6.7 一句话记忆

> **DCN：让原始特征不断参与后续计算，逐层组成更复杂的关系。**

# 7. LHUC / PPNet：按用户动态调节网络

## 7.1 核心定位

PPNet借鉴了LHUC的思想，通过用户、物品或场景等个性化先验信息，生成一组门控权重，用于动态缩放DNN中的隐藏单元。

它主要解决的问题不是：

```text
用户年龄和商品类别如何交叉？
```

而是：

```text
对于当前用户，
网络中的哪些能力应该被增强，
哪些能力应该被减弱？
```

因此，它更接近一种**个性化网络调节机制**。

## 7.2 类比：音乐均衡器

假设排序网络内部有多个隐藏单元：

```text
隐藏单元1：擅长识别游戏兴趣
隐藏单元2：擅长识别价格敏感
隐藏单元3：擅长识别作者偏好
隐藏单元4：擅长识别长短视频偏好
```

对于游戏用户，PPNet可能生成：

```text
游戏兴趣单元   × 1.8
价格敏感单元   × 0.5
作者偏好单元   × 1.1
视频时长单元   × 0.8
```

对于价格敏感用户，可能生成：

```text
游戏兴趣单元   × 0.4
价格敏感单元   × 1.9
作者偏好单元   × 0.7
视频时长单元   × 1.0
```

网络主体没有发生变化，但不同隐藏单元的“音量”被动态调整。

## 7.3 基本结构

```text
用户ID、用户画像、物品和场景信息
                ↓
          个性化门控网络
                ↓
       生成当前样本的门控权重
                ↓
      隐藏层输出 × 门控权重
                ↓
        个性化隐藏层表示
                ↓
             下一层
```

在多任务推荐中，还可以为不同任务塔生成不同门控：

```text
              用户个性化信息
                     ↓
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
   点击任务门控   点赞任务门控   时长任务门控
       ↓             ↓             ↓
   CTR Tower      Like Tower     Watch Tower
```

## 7.4 适用场景

PPNet适合：

- 用户数量大，个体差异明显；
- 同一特征对不同用户的意义不同；
- 多任务推荐；
- 多场景推荐；
- 不同用户的行为稀疏程度差异较大；
- 希望在共享网络基础上增强个性化。

例如短视频推荐中，不同用户可能分别更关注：

```text
用户A：点赞；
用户B：完整播放；
用户C：作者关系；
用户D：同城内容。
```

如果所有用户完全共享同一套隐藏表示，可能难以刻画这种差异。

## 7.5 优点

- 用户级、场景级个性化能力强；
- 可以插入已有DNN或多任务模型；
- 不需要为每个用户保存一套独立网络；
- 可以按用户、场景和任务动态调节；
- 适合大规模多任务精排模型。

## 7.6 缺点

- 它不是直接的特征交叉模块；
- 依赖个性化先验信息质量；
- 冷启动用户的个性化收益可能有限；
- 会增加门控网络的参数与推理成本；
- 门控输入、门控位置和门控层数都需要实验调优；
- 门控权重不应简单解释为因果意义上的特征重要性。

## 7.7 一句话记忆

> **PPNet：让不同用户使用同一网络时，重点激活不同的神经元能力。**

# 8. SENet + Bilinear：先挑重点，再精细交互

这类方法常以 **FiBiNET** 为代表，包含两个核心部分：

1. SENet：判断哪些Feature Field更重要；
2. Bilinear：更精细地建模两个Field之间的关系。

---

## 8.1 SENet：动态选择重要特征

假设当前样本包含：

```text
用户年龄
用户兴趣
用户城市
视频类别
视频作者
```

在不同样本中，这些特征的重要性并不相同。

例如推荐本地生活内容时：

```text
用户城市：很重要
商家城市：很重要
用户兴趣：较重要
用户年龄：一般
视频作者：较弱
```

SENet会根据当前样本，为每个特征域生成一个权重：

```text
用户年龄 × 0.4
用户兴趣 × 1.2
用户城市 × 1.8
视频类别 × 1.1
视频作者 × 0.6
```

它可以类比为：

> 舞台灯光师先判断当前场景中谁最重要，再把灯光打到关键角色身上。

这里的权重是按样本动态生成的，而不是永久固定。

---

## 8.2 Bilinear：学习更细粒度的交互方式

普通FM通常通过Embedding内积建模两个特征：

```text
用户兴趣向量 · 视频类别向量
```

这种交互方式简单、统一。

Bilinear交互会在两个特征向量之间加入一个可学习变换，使不同特征对可以采用更合适的交互方式。

直观上可以理解为：

```text
用户兴趣向量
      ↓
可学习的关系变换
      ↓
与视频类别向量发生交互
```

因此，它不仅学习：

```text
两个特征是否相关？
```

还会学习：

```text
应该从哪些维度、以什么方式比较这两个特征？
```

---

## 8.3 整体结构

```text
原始稀疏特征
      ↓
Embedding层
      ↓
多个Field Embedding
      │
      ├───────────────┐
      ↓               ↓
原始Embedding       SENet
      │               ↓
      │         加权后的Embedding
      ↓               ↓
Bilinear交互      Bilinear交互
      └───────┬───────┘
              ↓
          拼接交叉结果
              ↓
             DNN
              ↓
           输出分数
```

可以将整体过程概括为：

```text
先判断哪些特征重要；
再让重要特征进行更精细的二阶交互；
最后由DNN继续学习复杂关系。
```

## 8.4 适用场景

适合：

- Feature Field数量较多；
- 不同样本的特征重要性变化明显；
- 普通FM交互能力不足；
- CTR、CVR等精排任务；
- 希望增强二阶交叉表达能力。

## 8.5 优点

- 可以动态调整Feature Field的重要性；
- Bilinear比普通内积表达能力更强；
- 同时解决“谁重要”和“怎么交互”；
- 适合与DNN组合；
- 对多Field的CTR预估通常比较有效。

## 8.6 缺点

- 参数量和计算量高于FM；
- Field较多时，两两交互数量快速增长；
- Bilinear矩阵会带来额外内存开销；
- SENet权重不能简单视为严格的业务解释；
- 主要增强二阶交互，高阶关系仍依赖后续网络。

## 8.7 一句话记忆

> **SENet负责选择重要特征，Bilinear负责让特征以更精细的方式交流。**

---

# 9. 四种方法的对比

| 对比维度 | FM | DCN | LHUC / PPNet | SENet + Bilinear |
|---|---|---|---|---|
| 核心目标 | 二阶交叉 | 显式高阶交叉 | 个性化网络调节 | 动态选择与精细二阶交互 |
| 主要操作 | Embedding内积 | 多层Cross Layer | 门控缩放隐藏单元 | Field加权与双线性交互 |
| 主要交叉阶数 | 二阶 | 多阶 | 不是重点 | 主要二阶 |
| 是否强调个性化 | 弱 | 弱 | 很强 | 按样本调整Field权重 |
| 模型复杂度 | 低 | 中 | 中 | 中到较高 |
| 在线计算成本 | 低 | 中 | 中 | 中到较高 |
| 常见使用位置 | 粗排、轻量精排 | 精排 | 多任务、多场景精排 | CTR/CVR精排 |
| 最大优势 | 简单稳定 | 高阶交叉能力强 | 个性化能力强 | 交互更精细 |
| 主要不足 | 表达能力有限 | 需要调层数和结构 | 不是直接交叉模型 | 参数和计算成本较高 |

# 10. 工业系统中如何选择

## 10.1 FM：优先稳定与低成本

当业务更关注：

- 推理延迟；
- 模型稳定性；
- 稀疏特征处理；
- 快速建立基线；

可以优先考虑FM或DeepFM中的FM部分。

```text
简单、稳定、低延迟
        ↓
       FM
```

## 10.2 DCN：需要显式高阶交叉

当业务中存在较多：

```text
用户 × 物品 × 场景
```

的复杂组合，并且二阶交叉不够时，可以选择DCN。

```text
需要自动学习高阶关系
        ↓
       DCN
```

## 10.3 PPNet：需要用户级个性化

当不同用户、不同场景或不同任务之间差异很大时，可以考虑PPNet。

```text
同一套共享网络不够个性化
        ↓
      PPNet
```

## 10.4 SENet + Bilinear：需要精细交互

当Feature Field较多，并且不同Field的重要性和交互方式差异明显时，可以考虑FiBiNET类结构。

```text
需要先选重点，再增强二阶交互
        ↓
SENet + Bilinear
```

# 11. 这些模块可以组合使用

工业模型通常不是简单四选一。

一个较复杂的精排模型可能采用如下结构：

```text
用户、物品、场景特征
          ↓
       Embedding
          ↓
    SENet调整Field权重
          ↓
 FM / Bilinear学习二阶交叉
          ↓
    DCN学习显式高阶交叉
          ↓
       DNN深层表示
          ↓
 PPNet根据用户调节隐藏单元
          ↓
CTR、时长、点赞等多个任务塔
```

但实际系统不会无脑堆叠所有模块，因为模型越复杂，通常意味着：

- 参数量增加；
- 推理耗时增加；
- 显存和内存成本增加；
- 训练稳定性下降；
- 工程维护难度增加。

工业选型的核心不是“模型越复杂越好”，而是：

> 在离线指标、在线收益、延迟、吞吐量和资源成本之间取得平衡。

# 12. 从C++在线服务角度看模型差异

对于C++排序服务来说，不同交叉结构会直接影响在线推理成本。

## FM

在线计算主要是：

```text
Embedding查表
+ 有效特征两两内积
+ 分数累加
```

特点：

- 计算逻辑简单；
- 容易做批量化；
- 对CPU较友好；
- 比较适合低延迟粗排。

## DCN

在线计算主要是：

```text
Embedding查表
+ 多层Cross计算
+ MLP计算
```

特点：

- 计算量高于FM；
- 适合精排；
- 需要关注矩阵计算效率；
- 常通过ONNX Runtime、TensorRT或内部推理框架部署。

## PPNet

额外增加：

```text
个性化先验输入
+ 门控网络
+ 隐藏层逐元素缩放
```

特点：

- 每个请求或样本的门控结果可能不同；
- 更难完全复用固定中间结果；
- 需要控制门控层数量和维度。

## SENet + Bilinear

额外增加：

```text
Field权重计算
+ 大量Field Pair交互
+ Bilinear变换
```

特点：

- Field数量较多时计算量增长明显；
- 需要控制参与交叉的Field数；
- 可以通过裁剪、共享参数和低秩矩阵降低成本。

# 13. 学习阶段应该掌握到什么程度

当前阶段不需要推导每种模型的全部公式，但应该能够回答以下问题。

## FM

- 它主要做二阶特征交叉；
- 使用Embedding内积共享参数；
- 适合大规模稀疏特征；
- 优点是简单、稳定、成本低；
- 缺点是高阶表达能力有限。

## DCN

- 它通过Cross Layer学习显式高阶交叉；
- 通常与Deep Network并行；
- 适合精排和复杂特征组合；
- 优点是高阶交叉能力强；
- 缺点是结构与层数需要调优。

## PPNet

- 它主要是个性化门控，而非传统特征交叉；
- 根据用户、物品、场景生成隐藏单元权重；
- 适合多用户、多场景、多任务；
- 优点是个性化强；
- 缺点是增加复杂度并依赖先验质量。

## SENet + Bilinear

- SENet负责动态调整Field重要性；
- Bilinear负责增强二阶交互；
- 适合Field较多的CTR/CVR精排；
- 优点是交互表达细致；
- 缺点是参数量和计算成本较高。


# 15. 核心结论

推荐系统的特征交叉，不只是将多个特征简单组合起来，而是为了让模型理解：

```text
什么用户
在什么场景
会对什么物品
产生什么行为
```

FM、DCN、PPNet和SENet + Bilinear分别从不同角度增强模型：

- FM提升二阶交叉能力；
- DCN提升显式高阶交叉能力；
- PPNet提升用户和场景个性化能力；
- SENet + Bilinear提升特征选择与二阶交互精细度。

学习这些模型时，最重要的不是记住复杂公式，而是先建立以下工程认知：

> 模型究竟在增强哪一类关系表达，它带来了多少收益，又增加了多少计算与工程成本。
