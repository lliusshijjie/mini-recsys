# 推荐系统粗排模型学习笔记

## 1. 粗排模型是什么

粗排（Pre-Ranking）位于召回和精排之间，主要作用是：

> 从召回得到的数千到数万个候选中，快速筛掉明显不合适的物品，并尽可能保留精排真正需要的优质候选。

典型链路如下：

```text
全量物品库
   ↓
多路召回
   ↓
5000～20000 个候选
   ↓
粗排
   ↓
500～1500 个候选
   ↓
精排
   ↓
50～200 个候选
   ↓
重排
```

粗排可以理解为：

> 召回与精排之间的高速候选压缩器。

---

# 2. 粗排的核心目标

粗排的主要目标不是完成最终排序，而是在很低的计算成本下完成候选筛选。

可以概括为三个关键词：

```text
低成本
高吞吐
少误杀
```

其中最重要的是“少误杀”。

因为候选一旦在粗排阶段被淘汰，后面的精排模型再准确，也无法恢复该候选。

因此，粗排通常遵循：

> 宁可多保留一些普通候选，也不要提前过滤掉真正优质的候选。

---

# 3. 粗排与精排的区别

| 维度 | 粗排 | 精排 |
|---|---|---|
| 候选数量 | 数千到数万 | 数百到上千 |
| 核心目标 | 快速筛选、尽量不误杀 | 准确预测最终顺序 |
| 特征数量 | 较少 | 较多 |
| 模型复杂度 | 轻量 | 较复杂 |
| 特征交叉 | 较弱 | 较强 |
| 序列建模 | 简化或不使用 | 经常使用 |
| 计算预算 | 极低 | 相对更高 |
| 主要风险 | 优质候选被过滤 | 候选顺序不准确 |

可以简单记忆为：

```text
粗排：又快，又不能漏掉好内容
精排：在剩余候选中准确区分谁更好
```

---

# 4. 粗排通常使用哪些特征

粗排候选量很大，因此特征设计必须强调：

> 获取成本低、覆盖率高、延迟稳定。

常见特征包括：

## 4.1 用户侧特征

```text
用户 ID Embedding
用户长期兴趣 Embedding
用户短期兴趣 Embedding
用户活跃等级
用户历史 CTR
少量用户画像特征
```

## 4.2 物品侧特征

```text
物品 ID Embedding
物品类目
作者 ID
发布时间
热度
质量分
简单统计特征
```

## 4.3 匹配与召回特征

```text
用户向量与物品向量相似度
召回来源
召回分数
召回通道优先级
用户与物品类目匹配度
```

## 4.4 场景特征

```text
当前时间
设备类型
推荐入口
当前页面
网络环境
```

粗排通常避免使用：

- 大量远程特征；
- 超长用户行为序列；
- 复杂图文 Token；
- Cross-Attention；
- 大型 Transformer；
- 高维且稀疏的复杂交叉特征。

---

# 5. 常见粗排模型

## 5.1 向量内积模型

最简单的粗排形式：

\[
Score(u,i)=e_u^\top e_i
\]

其中：

- \(e_u\)：用户向量；
- \(e_i\)：物品向量。

优点：

- 计算速度快；
- 易于批量计算；
- 适合 SIMD；
- 用户和物品向量可以提前缓存；
- 推理成本很低。

缺点：

- 用户与物品交互较弱；
- 只能表达有限的匹配关系；
- 难以使用复杂上下文。

---

## 5.2 轻量级 DNN

将少量用户、物品和场景特征拼接后输入一个小型 MLP：

\[
Score=MLP([e_u,e_i,x_{context}])
\]

典型结构：

```text
用户 Embedding
物品 Embedding
类目 Embedding
召回分数
热度特征
少量场景特征
      ↓
2～3 层轻量 MLP
      ↓
粗排分数
```

优点：

- 比纯内积表达能力更强；
- 可以学习简单特征交叉；
- 仍然能够控制计算成本。

缺点：

- 候选量很大时，推理成本仍然需要严格控制。

---

## 5.3 轻量 Wide & Deep / DeepFM / DCN

对于离散特征和简单交叉较多的业务，也可以采用：

```text
简化版 Wide & Deep
小型 DeepFM
轻量 DCN
GBDT + LR
轻量树模型
```

工程中通常会严格限制：

- 网络层数；
- 隐藏层宽度；
- Embedding 维度；
- 特征数量；
- 特征读取次数。

---

## 5.4 精排模型蒸馏

蒸馏是工业粗排中非常常见的做法。

整体流程：

```text
精排模型作为 Teacher
        ↓
生成精排分数或软标签
        ↓
轻量粗排模型作为 Student
        ↓
学习精排模型的判断能力
```

损失函数可以写成：

\[
L=
\alpha L_{label}
+\beta L_{distill}
\]

其中：

\[
L_{distill}
=
(\hat s_{pre}-s_{fine})^2
\]

粗排不只学习用户是否点击，还学习精排模型对候选的综合判断。

蒸馏的核心价值是：

> 让粗排在保持低成本的同时，尽可能接近精排的排序结果。

---

# 6. 粗排模型训练什么

粗排常见训练方式有三类。

## 6.1 使用真实用户行为标签

例如：

```text
点击：正样本
曝光未点击：负样本
```

模型预测：

\[
pCTR=P(click|u,i)
\]

也可以预测：

- 有效播放；
- 完播；
- 转化；
- 点赞；
- 负反馈。

但如果精排优化的是多目标，粗排只训练 CTR，二者目标可能不一致。

---

## 6.2 拟合精排分数

让粗排模型直接学习精排模型输出：

\[
\hat s_{pre}\approx s_{fine}
\]

这样可以提高粗排与精排的一致性。

适合用于：

```text
保留精排高分候选
降低粗排误杀
缩小粗排和精排目标差距
```

---

## 6.3 Pairwise 排序训练

构造正负候选对：

\[
L=
-\log \sigma(s_{positive}-s_{negative})
\]

它要求：

> 优质候选的粗排分数高于低质量候选。

Pairwise 训练直接关注候选之间的相对顺序，而不是只关注单个样本的绝对预测值。

---

## 6.4 多种训练目标联合

工业中常将多种目标组合：

\[
L=
\alpha L_{behavior}
+\beta L_{distill}
+\gamma L_{pairwise}
\]

其中：

- \(L_{behavior}\)：学习真实点击、播放或转化标签；
- \(L_{distill}\)：拟合精排分数；
- \(L_{pairwise}\)：学习候选相对顺序。

---

# 7. 粗排最重要的评价指标

粗排不能只看 AUC，因为它的主要任务不是产生最终顺序，而是为精排保留候选。

## 7.1 精排 Top-K 保留率

假设精排在全部候选中得到理想 Top-K：

\[
Retention@K=
\frac{
|\text{粗排保留集合}\cap\text{精排 Top-K}|
}{K}
\]

例如：

```text
精排理想 Top-100
粗排保留其中 96 个
Retention@100 = 96%
```

这是粗排非常关键的指标。

---

## 7.2 Top-K 重合率

比较：

```text
粗排 Top-K
与
精排 Top-K
```

两者交集越大，说明粗排越接近精排。

---

## 7.3 排序一致性

常见指标包括：

```text
Pairwise 一致率
Spearman 相关系数
Kendall 相关系数
```

这些指标用于衡量粗排分数与精排分数的排序关系是否一致。

---

## 7.4 AUC / GAUC

AUC 和 GAUC 仍然可以用于衡量模型区分正负样本的能力，但不能作为唯一评价指标。

粗排可能 AUC 很高，但如果精排 Top-K 保留率不高，仍然不是一个合格模型。

---

## 7.5 工程指标

粗排还必须关注：

```text
平均延迟
P95 / P99 延迟
QPS
单候选计算成本
CPU 使用率
内存占用
特征读取耗时
批量推理吞吐
```

粗排评价本质上是：

\[
效果 \div 计算成本
\]

一个模型即使离线效果略好，但延迟和资源成本增加很多，也未必值得上线。

---

# 8. 粗排在线服务流程

一个典型的 C++ 粗排服务流程如下：

```text
接收召回候选
    ↓
读取用户向量和少量用户特征
    ↓
批量读取物品轻量特征
    ↓
构造连续特征矩阵
    ↓
批量模型推理
    ↓
选择 Top-K
    ↓
交给精排
```

伪代码：

```cpp
std::vector<Candidate> pre_rank(
    const UserFeatures& user,
    std::vector<Candidate> candidates,
    std::size_t top_k
) {
    auto item_features =
        feature_store.batch_get(candidates);

    FeatureMatrix input(
        candidates.size(),
        feature_dim
    );

    for (std::size_t i = 0; i < candidates.size(); ++i) {
        fill_pre_rank_features(
            input.row(i),
            user,
            item_features[i],
            candidates[i].recall_score
        );
    }

    const auto scores = model.predict(input);

    for (std::size_t i = 0; i < candidates.size(); ++i) {
        candidates[i].pre_rank_score = scores[i];
    }

    if (candidates.size() > top_k) {
        std::nth_element(
            candidates.begin(),
            candidates.begin() + top_k,
            candidates.end(),
            [](const Candidate& lhs, const Candidate& rhs) {
                return lhs.pre_rank_score >
                       rhs.pre_rank_score;
            }
        );

        candidates.resize(top_k);
    }

    return candidates;
}
```

---

# 9. 为什么要使用批量推理

错误方式：

```cpp
for (const auto& candidate : candidates) {
    auto score = model.predict(candidate);
}
```

这种逐候选推理会产生大量：

- 函数调用；
- Tensor 构造；
- 动态内存分配；
- 推理框架调度；
- GPU Kernel Launch；
- Cache Miss。

更合理的方式是：

```text
所有候选特征
    ↓
构造 [candidate_count, feature_dim] Tensor
    ↓
一次或少量几次批量推理
    ↓
得到全部候选分数
```

粗排候选量大，请求内 Batch 是核心优化措施。

---

# 10. Top-K 选择

粗排通常只需要保留前 K 个候选，不需要对全部候选完整排序。

完整排序：

```cpp
std::sort(candidates.begin(), candidates.end(), compare);
```

复杂度：

\[
O(N\log N)
\]

如果只需要 Top-K，可以使用：

```cpp
std::nth_element(
    candidates.begin(),
    candidates.begin() + k,
    candidates.end(),
    compare
);
```

平均复杂度接近：

\[
O(N)
\]

如果要求前 K 个内部有序，再单独排序前 K 个即可。

# 11. 粗排常见工程优化

## 11.1 批量特征读取

避免逐候选访问 Feature Store：

```text
错误：每个候选一次 RPC
正确：一次批量请求读取全部物品特征
```

## 11.2 连续内存布局

使用连续数组存储特征：

```cpp
std::vector<float> features(
    candidate_count * feature_dim
);
```

避免大量 `vector<vector<float>>` 和小对象分配。

## 11.3 本地缓存

适合缓存：

```text
物品静态特征
物品 Embedding
类目和作者特征
轻量统计特征
```

可以降低远程存储压力和尾延迟。

## 11.4 SIMD 与多线程

向量内积和小型 DNN 可以使用：

```text
SIMD
候选分块并行
线程池
CPU 亲和性
NUMA 优化
```

但需要避免线程池嵌套造成过度调度。

## 11.5 对象池和内存复用

粗排每个请求需要处理大量候选，应尽量复用：

```text
特征 Buffer
Tensor
候选数组
中间结果对象
```

减少堆分配和 P99 抖动。

## 11.6 超时降级

当粗排模型超时或剩余预算不足时，可以：

```text
减少候选处理数量
切换更轻量模型
使用召回分数
使用召回分数 + 热度
直接按通道优先级截断
```

# 12. 粗排常见问题

## 12.1 误杀优质候选

这是粗排最严重的问题。

一旦优质候选被过滤，后续精排无法恢复。

应重点监控：

```text
Retention@K
长尾候选保留率
新物品保留率
各召回通道保留率
```

---

## 12.2 模型过于简单

模型太简单虽然速度快，但可能无法学习用户与物品的有效匹配关系。

表现为：

```text
Top-K 保留率低
粗排和精排一致性差
高价值候选被大量误杀
```

---

## 12.3 模型过于复杂

粗排模型太复杂时，会导致：

```text
推理延迟增加
CPU/GPU 成本提高
候选吞吐下降
P99 抖动明显
```

如果粗排成本接近精排，粗排就失去了意义。

---

## 12.4 训练目标与精排不一致

例如：

```text
粗排只优化 CTR
精排优化时长、点赞、转化和负反馈
```

粗排可能提前淘汰精排认为有价值的候选。

解决方式：

- 使用精排蒸馏；
- 使用多任务训练；
- 增加 Pairwise Loss；
- 直接优化精排 Top-K 保留率相关目标。

---

## 12.5 特征成本过高

粗排候选多，如果每个候选都读取复杂远程特征，会导致严重的延迟和存储压力。

因此应优先选择：

```text
本地可得
可批量读取
可提前缓存
覆盖率高
计算简单
```

的特征。

---

# 13. 粗排设计中的核心权衡

粗排模型始终在权衡：

\[
模型效果
\quad vs \quad
计算成本
\]

模型更复杂，可能提高保留率，但也会提高延迟和资源成本。

模型更简单，速度更快，但可能误杀优质候选。

因此粗排追求的不是最高离线精度，而是：

> 在严格延迟和资源预算下，尽可能提高精排优质候选的保留率。

```text

```

```text
低成本
高吞吐
少误杀
```

粗排的主要模型：

```text
向量内积
轻量 DNN
简化 Wide & Deep / DeepFM / DCN
精排蒸馏模型
```

粗排的关键指标：

```text
精排 Top-K 保留率
排序一致性
AUC / GAUC

```

最值得记住的一句话是：

> 粗排不追求完成最终排序，而是在极低计算成本下，将数千候选压缩到数百，并尽可能保留精排真正需要的优质候选。
