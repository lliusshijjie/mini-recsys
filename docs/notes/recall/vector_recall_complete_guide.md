# 推荐系统向量召回阶段完整总结

## 1. 召回层的职责

推荐系统通常采用漏斗式架构：

```text
全量物品库：千万 / 亿级
        ↓
召回层：几百 / 几千
        ↓
粗排：几百
        ↓
精排：几十
        ↓
重排：最终展示
```

召回层的核心任务是：

> 在极短时间内，从海量物品中找出一批用户可能感兴趣的候选。

召回层更强调：

- **高召回率**：尽量不要漏掉潜在兴趣物品；
- **低延迟**：通常要求毫秒级返回；
- **高吞吐**：支持大量并发请求；
- **多样性**：避免候选全部来自同一兴趣或热门物品；
- **可扩展性**：可以不断增加新的召回通道。

召回层通常不是单一算法，而是多个召回通道并行工作：

```text
双塔向量召回
ItemCF / Swing
矩阵分解召回
作者召回
地理位置召回
热门 / 新品召回
缓存召回
        ↓
合并、去重、过滤
        ↓
进入粗排
```

## 2. 离散特征与 Embedding

### 2.1 离散特征

推荐系统中的常见离散特征包括：

```text
user_id、item_id、category_id、author_id、city_id、device_type、tag_id
```

它们本质上是类别或 ID，不能直接参与神经网络数值计算。最简单的处理方式是 One-Hot，但 user_id、item_id 往往是千万级甚至亿级，One-Hot 会产生极高维、极稀疏的向量，因此工业系统主要使用 Embedding。

### 2.2 Embedding

假设一个离散特征共有 \(N\) 个取值，Embedding 维度为 \(d\)，模型维护矩阵：

\[
E\in\mathbb{R}^{N\times d}
\]

某个 ID \(i\) 的向量：

\[
e_i=E[i]
\]

程序上可以理解为查表：

```cpp
embedding = embedding_table[id];
```

例如：

```text
C++ 教程   -> [0.90, 0.10, 0.20]
Rust 教程  -> [0.85, 0.20, 0.25]
篮球视频   -> [0.10, 0.80, 0.70]
```

经过训练后，相似物品会在向量空间中更接近。

### 2.3 Multi-Hot 特征

用户可能拥有多个兴趣标签，例如 `[C++, Rust, Linux]`。每个标签先查 Embedding，再通过 Pooling 聚合：

\[
e_{\text{tags}}=\frac{1}{n}\sum_{k=1}^{n}e_k
\]

常见聚合方式包括 Mean、Sum、Max 和 Attention Pooling。

## 3. Embedding 向量从哪里来

Embedding 不是人工编写的，而是通过训练数据学习出来的。训练开始时，Embedding 通常是随机初始化的小数：

```text
user_1001 -> [0.012, -0.031, 0.008, ...]
item_8888 -> [-0.017, 0.024, 0.005, ...]
```

用户点击、收藏或购买物品后，模型通过损失函数和反向传播调整向量：

\[
E[u]\leftarrow E[u]-\eta\frac{\partial L}{\partial E[u]}
\]

\[
E[i]\leftarrow E[i]-\eta\frac{\partial L}{\partial E[i]}
\]

经过大量样本训练后：

```text
用户向量会靠近其喜欢的物品
相似物品会形成相近的向量区域
不相关物品会相对远离
```

需要区分三种向量：

| 向量类型 | 来源 |
|---|---|
| ID Embedding | 随机初始化后由行为数据训练得到 |
| 双塔最终向量 | 多种特征经过用户塔或物品塔计算得到 |
| 内容 Embedding | 由 BERT、ViT 等文本或图像模型编码得到 |

## 4. 矩阵补全与矩阵分解

### 4.1 用户—物品交互矩阵

构造矩阵：

\[
R\in\mathbb{R}^{m\times n}
\]

其中 \(R[u][i]\) 表示用户 \(u\) 对物品 \(i\) 的反馈。矩阵补全的目标是预测未知位置。

### 4.2 矩阵分解

将用户和物品映射到低维空间：

\[
P\in\mathbb{R}^{m\times k},\qquad Q\in\mathbb{R}^{n\times k}
\]

预测分数：

\[
\hat{R}_{ui}=p_u^Tq_i
\]

优化目标：

\[
\min_{P,Q}\sum_{(u,i)\in\Omega}(R_{ui}-p_u^Tq_i)^2+\lambda(\|p_u\|^2+\|q_i\|^2)
\]

矩阵分解最终同样得到 user embedding 和 item embedding，因此可以继续使用 ANN 做向量召回。

## 5. 最近邻查找

给定查询向量 \(q\)，从物品向量集合中找最相似的 TopK：

\[
TopK(q)=\operatorname{argTopK}_{x_i}sim(q,x_i)
\]

在推荐系统中，\(q\) 是用户向量，\(x_i\) 是物品向量。

常见相似度：

### 点积

\[
score(u,i)=p_u^Tq_i
\]

### 余弦相似度

\[
sim(u,i)=\frac{p_u^Tq_i}{\|p_u\|\|q_i\|}
\]

如果向量已经归一化，余弦相似度等价于点积。

### 欧氏距离

\[
dist(u,i)=\sqrt{\sum_{j=1}^{d}(p_{u,j}-q_{i,j})^2}
\]

距离越小越相似。

## 6. 精确最近邻与 ANN

### 6.1 精确最近邻

暴力扫描全部物品，复杂度为：

\[
O(n\cdot d)
\]

当物品达到千万或亿级时，线上无法接受。

### 6.2 近似最近邻 ANN

ANN 允许少量漏召，换取低延迟和高吞吐。

#### HNSW

分层近邻图，高层快速跳转、底层精细搜索。优点是查询快、召回率高，缺点是内存占用大、建图成本较高。关键参数包括 `M`、`efConstruction`、`efSearch`。

#### IVF

先通过 KMeans 把向量划分成多个簇，查询时只搜索最近的若干个簇。关键参数包括 `nlist` 和 `nprobe`。

#### PQ

把高维向量切成多个子向量，每个子向量用码本编号表示，显著压缩内存，但会损失精度。

#### IVF-PQ

```text
IVF：缩小搜索范围
PQ：压缩向量并加速距离估算
```

适合超大规模物品库。

## 7. 双塔模型

### 7.1 模型结构

用户塔：

\[
p_u=f_\theta(x_u)
\]

物品塔：

\[
q_i=g_\phi(x_i)
\]

匹配分数：

\[
s(u,i)=p_u^Tq_i
\]

用户塔输入可能包括 user_id、城市、设备、最近点击序列、长期兴趣标签和实时上下文；物品塔输入可能包括 item_id、类目、作者、标签、文本、图片、价格和时间。

### 7.2 为什么双塔适合召回

双塔最大的工程价值是用户和物品可以分开计算。

```text
离线：物品塔批量生成 item embedding → 构建 ANN 索引
在线：用户塔生成 user embedding → ANN 查询 TopK
```

这样避免了对全部物品逐个执行复杂模型。

## 8. 双塔训练：Pointwise、Pairwise、Listwise

三种训练方式训练的是同一套参数：用户 ID Embedding、物品 ID Embedding、用户塔参数、物品塔参数及其他特征 Embedding。它们本质上都在塑造用户—物品向量空间。

### 8.1 Pointwise

样本：

\[
(u,i,y)
\]

预测：

\[
\hat{y}=\sigma(s(u,i))=\frac{1}{1+e^{-s(u,i)}}
\]

损失：

\[
L_{\text{point}}=-[y\log\hat{y}+(1-y)\log(1-\hat{y})]
\]

它学习的是单个用户—物品是否匹配。

### 8.2 Pairwise

样本：

\[
(u,i^+,i^-)
\]

目标：

\[
s(u,i^+)>s(u,i^-)
\]

BPR 损失：

\[
L_{\text{BPR}}=-\log\sigma(s(u,i^+)-s(u,i^-))
\]

Hinge Loss：

\[
L_{\text{hinge}}=\max(0,m-s(u,i^+)+s(u,i^-))
\]

它学习的是正样本和负样本的相对顺序。

### 8.3 Listwise

候选列表：

\[
C_u=\{i_1,i_2,\ldots,i_n\}
\]

Softmax：

\[
P(i_j|u)=\frac{\exp(s(u,i_j)/\tau)}{\sum_k\exp(s(u,i_k)/\tau)}
\]

正样本损失：

\[
L_{\text{list}}=-\log P(i^+|u)
\]

它学习的是正样本在整个候选列表中的竞争能力。

### 8.4 In-Batch Negative

一个 Batch 中其他用户的正样本，可作为当前用户的负样本。分数矩阵为：

\[
S_{ab}=p_a^Tq_b
\]

训练时希望对角线分数最高。

## 9. 正负样本构造

### 正样本

```text
曝光并点击、收藏、加购、购买、完播、点赞、关注
```

可按行为价值设置不同权重。

### 简单负样本

```text
全体物品随机采样
Batch 内其他物品
```

优点是构造简单、数量充足；缺点是经常过于容易。

### 困难负样本

```text
被召回但被后续排序淘汰
旧模型召回但用户未选择
和正样本同类目、同主题
```

困难负样本更有训练价值，但也更容易是假负样本。

### 假负样本

需要注意：

```text
未点击 ≠ 不喜欢
```

未点击可能因为位置靠后、没有看到、时间不足或已经点击了其他物品，因此曝光未点击不宜全部作为强负样本。

## 10. 多路召回与配额控制

常见召回路径：

```text
双塔向量召回
ItemCF / Swing
矩阵分解
作者召回
地理位置召回
热门 / 新品召回
标签召回
缓存召回
```

不同业务中，占大头的通道不同：

| 场景 | 常见主力召回 |
|---|---|
| 普通信息流 | 双塔 + ItemCF / Swing |
| 电商 | 双塔 + ItemCF + 类目关系 |
| 本地生活 | 地理位置召回 |
| 关注流 | 作者召回 |
| 新用户 | 热门、人群、上下文召回 |

没有固定配额比例。第一版可以采用硬配额，后续根据独占贡献率、后续通过率、点击贡献、覆盖率、长尾占比、延迟和资源成本调整。

不同通道的原始分数通常不可直接比较，因此常见做法是：

```text
各路按配额召回
        ↓
合并、去重
        ↓
保留召回来源
        ↓
统一交给粗排模型打分
```

## 11. Bloom Filter：已看物品过滤

Bloom Filter 主要用于快速判断某个物品是否可能已经被用户看过。

召回候选通常需要过滤：

```text
已经曝光过
已经点击过
已经购买过
用户明确不感兴趣
```

如果为每个用户保存完整已看集合，内存开销可能很大。Bloom Filter 使用较少内存提供快速集合判断。

### 11.1 基本原理

Bloom Filter 使用一个位数组和多个哈希函数。插入物品 \(x\) 时，计算：

\[
h_1(x),h_2(x),\ldots,h_k(x)
\]

并把对应位设置为 1。

查询时：

- 如果某一位为 0：该元素一定没出现过；
- 如果全部为 1：该元素可能出现过。

因此 Bloom Filter：

```text
不会出现假阴性
可能出现假阳性
```

在召回过滤中的含义是：已看物品不会漏掉，但少量未看物品可能被误过滤。

### 11.2 在召回链路中的位置

```text
多路召回候选
        ↓
Bloom Filter 检查已看集合
        ↓
过滤可能已看物品
        ↓
业务过滤
        ↓
进入粗排
```

Bloom Filter 适合做第一层快速过滤，必要时可以再用精确集合复核。

## 12. 双塔模型更新

### 12.1 全量更新

更新全部参数：

\[
\theta_{t+1}=\theta_t-\eta\nabla_\theta L(D_t;\theta_t)
\]

通常包括用户 ID Embedding、物品 ID Embedding、用户塔和物品塔参数。全量更新后，需要重新计算 item embedding 并重建 ANN 索引。

### 12.2 增量更新

常见方式是冻结全连接层，只更新用户 ID Embedding：

\[
E_u'=E_u-\eta\frac{\partial L}{\partial E_u}
\]

作用是快速跟踪用户近期兴趣。

实际系统通常采用：

```text
定期全量更新
+
高频增量更新
+
实时行为特征
```

## 13. 头部效应

头部效应指少量热门物品占据大部分曝光和点击，大量长尾物品很难获得展示机会。

基本关系：

\[
Click_i=Exposure_i\times CTR_i
\]

典型正反馈：

```text
更多曝光
   ↓
更多点击
   ↓
更多训练样本
   ↓
Embedding 训练更充分
   ↓
模型得分更高
   ↓
继续获得更多曝光
```

这会产生曝光偏差：上一版模型决定曝光，曝光决定点击数据，点击数据再训练下一版模型。

## 14. 自监督学习缓解头部效应

自监督学习不完全依赖点击标签，而是从用户行为自身构造辅助任务。

总损失：

\[
L_{\text{total}}=L_{\text{retrieval}}+\lambda L_{\text{SSL}}
\]

### 14.1 用户行为对比学习

对同一用户构造两个不同视图，例如随机掩码、删除、裁剪和局部重排：

\[
z_u^{(1)}=f_\theta(\tilde{x}_u^{(1)}),\qquad z_u^{(2)}=f_\theta(\tilde{x}_u^{(2)})
\]

InfoNCE：

\[
L_{\text{CL}}=-\sum_u\log\frac{\exp(sim(z_u^{(1)},z_u^{(2)})/\tau)}{\sum_v\exp(sim(z_u^{(1)},z_v^{(2)})/\tau)}
\]

目标是拉近同一用户的不同视图，推远不同用户表示。

### 14.2 流行度感知增强

热门物品以更高概率被删除：

\[
P_{\text{drop}}(i)\propto pop(i)^\gamma
\]

这样可以减少用户表示对少数热门物品的依赖。

### 14.3 长尾样本加权

\[
w_i=\frac{1}{(freq(i)+\epsilon)^\beta}
\]

长尾物品每个样本获得更高梯度权重。

### 14.4 掩码行为预测

随机遮挡用户行为，让模型预测被遮挡物品：

\[
P(i_m|u)=\frac{\exp(z_{u,-m}^Tv_{i_m}/\tau)}{\sum_j\exp(z_{u,-m}^Tv_j/\tau)}
\]

自监督学习不能单独解决头部效应，还需要结合负采样修正、探索流量、新品召回、长尾召回和重排多样性。

## 15. 线上向量召回完整流程

### 离线阶段

```text
用户行为日志
        ↓
构造正负样本
        ↓
训练双塔 / 矩阵分解
        ↓
生成所有 item embedding
        ↓
构建 HNSW / Faiss / IVF-PQ 索引
        ↓
发布模型和索引
```

### 在线阶段

```text
user_id
        ↓
读取用户 ID Embedding / 用户画像 / 实时行为
        ↓
用户塔生成最终 user embedding
        ↓
查询 ANN 向量索引
        ↓
得到 TopK 物品
        ↓
与其他召回通道合并
        ↓
Bloom Filter 过滤已看物品
        ↓
去重、业务过滤、截断
        ↓
进入粗排
```

## 16. 核心总结

整个向量召回阶段可以归纳为五个核心问题：

```text
向量怎么来：离散特征 → Embedding → 双塔 / 矩阵分解
怎么找物品：user embedding → ANN → TopK item
怎么训练：Pointwise / Pairwise / Listwise
怎么融合：多路按配额召回 → 合并去重 → 统一粗排
怎么长期优化：全量更新、增量更新、自监督、困难负样本、探索策略
```

向量召回的核心价值是：

> 把海量物品逐个打分的问题，转化为用户向量与物品向量之间的高效最近邻检索问题。
