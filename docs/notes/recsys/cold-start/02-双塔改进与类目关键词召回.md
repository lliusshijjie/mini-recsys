# 物品冷启动中的召回策略：双塔模型改进与类目、关键词召回

## 1. 背景：为什么新物品难以进入召回结果

在推荐系统中，双塔模型通常会分别计算：

- 用户向量 `user_embedding`
- 物品向量 `item_embedding`

在线召回时，再根据两个向量的相似度，从海量物品中找出与用户最匹配的一批候选物品：

```text
用户特征
   ↓
用户塔
   ↓
user_embedding
   ↓
与物品向量库做 ANN 检索
   ↓
召回 TopK 物品
```

对于已经积累了大量点击、点赞、购买等行为的老物品，模型通常能学到较稳定的物品向量。

但新物品刚刚发布时，往往存在两个问题：

1. 没有物品 ID 的历史训练样本；
2. 没有点击、互动和消费行为。

这会导致双塔模型无法为新物品生成可靠的 ID Embedding，甚至这个新物品 ID 根本没有出现在训练词表中。

如果不做额外处理，新物品可能根本进不了向量召回池。

因此，物品冷启动阶段常见的做法是：

```text
双塔模型改进
    +
类目召回
    +
关键词召回
    +
其他规则或热门兜底
```

其中：

- 双塔模型负责尽可能利用已有特征生成向量；
- 类目和关键词召回负责提供简单、稳定、可解释的冷启动通道。

---

# 2. 双塔模型在冷启动中的问题

一个简单的物品塔可能输入以下特征：

```text
物品 ID
类目
作者 ID
关键词
文本特征
图片特征
价格
发布时间
```

其中，物品 ID 往往是非常强的特征，因为模型可以直接记住某个物品过去表现如何。

例如：

```text
item_id = 10001
        ↓
Embedding Table 查询
        ↓
得到该物品的 ID Embedding
```

但对于一个刚发布的新物品：

```text
item_id = 999999
```

这个 ID 可能没有在训练阶段出现过，因此无法查到对应的 Embedding。

这就是冷启动场景中的 **Out-of-Vocabulary，简称 OOV** 问题。

可以简单理解为：

> 模型的“物品字典”里没有这个新物品。

---

# 3. Default Embedding 是什么

## 3.1 基本思想

当新物品 ID 不存在于 Embedding Table 中时，不直接报错，也不让向量为空，而是给它一个预先准备好的默认向量：

```text
新物品 ID 未命中
       ↓
使用 Default Embedding
       ↓
再与类目、关键词、作者等特征组合
       ↓
生成最终 item_embedding
```

例如：

```text
item_id_embedding =
    item_id 在词表中 ? lookup(item_id)
                     : default_embedding
```

可以把 Default Embedding 理解为：

> 模型不认识这个新物品时，先给它一张“临时通行证”。

这张通行证本身不能准确表达新物品的个性，但至少能让它进入模型计算流程。

---

## 3.2 最简单的实现方式

最简单的方法是为所有未知新物品使用同一个默认向量：

```text
unknown_item_embedding = [0.01, -0.03, 0.02, ...]
```

伪代码如下：

```cpp
Embedding get_item_id_embedding(ItemId item_id) {
    auto iter = embedding_table.find(item_id);

    if (iter != embedding_table.end()) {
        return iter->second;
    }

    return default_embedding;
}
```

这种方式实现简单，但存在一个明显问题：

> 所有新物品的 ID Embedding 都完全一样。

因此，真正区分新物品的任务，就要交给类目、关键词、作者、文本和图片等内容特征。

---

# 4. 冷启动双塔模型如何改造

## 4.1 不再只依赖物品 ID

冷启动场景中，物品塔不能过度依赖 `item_id_embedding`。

更合理的物品塔输入可以是：

```text
item_id_embedding
category_embedding
keyword_embedding
author_embedding
text_embedding
image_embedding
statistics_features
```

最终将它们拼接或融合：

```text
item_features =
    concat(
        item_id_embedding,
        category_embedding,
        keyword_embedding,
        author_embedding,
        text_embedding,
        image_embedding
    )
```

然后送入多层神经网络：

```text
item_features
    ↓
MLP
    ↓
item_embedding
```

对于老物品：

```text
物品 ID 特征 + 内容特征 + 统计特征
```

对于新物品：

```text
Default Embedding + 内容特征 + 作者特征
```

即使物品 ID 没有历史信息，模型仍可以根据内容判断：

- 它属于什么类目；
- 它表达了哪些关键词；
- 它由哪个作者发布；
- 它的文本和图片主要在讲什么。

---

## 4.2 物品塔改造后的结构

```text
                    ┌────────────────────┐
新物品 ID ────────→│ ID Embedding 查询   │
                    │ 未命中则用 Default │
                    └─────────┬──────────┘
                              │
类目 ─────────────→ Category Embedding
关键词 ───────────→ Keyword Embedding
作者 ─────────────→ Author Embedding
文本/图片 ────────→ Content Embedding
                              │
                              ↓
                         特征拼接
                              ↓
                            MLP
                              ↓
                       item_embedding
```

这个结构的关键思想是：

> ID 特征只是物品表示的一部分，而不是全部。

---

# 5. Default Embedding 的几种常见设计

## 5.1 全局 Default Embedding

所有新物品使用同一个默认向量：

```text
new_item → global_default_embedding
```

优点：

- 实现最简单；
- 工程成本低；
- 可以快速上线。

缺点：

- 所有新物品的 ID 表示完全相同；
- 依赖其他内容特征完成区分；
- 个性化能力较弱。

适合：

- 第一版冷启动系统；
- 新物品数量不大；
- 内容特征已经比较丰富。

---

## 5.2 按类目设置 Default Embedding

不同类目使用不同的默认向量：

```text
手机类新商品   → phone_default_embedding
图书类新商品   → book_default_embedding
服装类新商品   → clothes_default_embedding
```

例如：

```cpp
Embedding get_default_embedding(CategoryId category_id) {
    auto iter = category_default_embeddings.find(category_id);

    if (iter != category_default_embeddings.end()) {
        return iter->second;
    }

    return global_default_embedding;
}
```

这种方式比全局默认向量更合理，因为同一类目的新物品通常具有一定共性。

可以理解为：

> 系统虽然不认识这个具体商品，但至少知道它是一部手机，而不是一本书。

---

## 5.3 使用类目平均向量

还可以将某个类目中已有老物品的向量求平均，作为新物品的默认表示：

```text
category_default_embedding
    =
同类目老物品 Embedding 的平均值
```

例如：

```text
数码类目已有 10000 个老物品
        ↓
计算这些物品向量的平均值
        ↓
作为数码类新物品的初始向量
```

优点：

- 比随机向量或全局默认向量更符合业务语义；
- 新物品更容易召回给对该类目感兴趣的用户。

缺点：

- 类目内部差异可能很大；
- 平均向量可能过于“平庸”；
- 对细粒度兴趣表达不足。

---

## 5.4 只弱化 ID Embedding 权重

还有一种方式不是完全替换，而是在训练和线上计算时降低 ID 特征的权重：

```text
item_embedding =
    0.2 × item_id_feature
  + 0.8 × content_feature
```

对于老物品，ID 特征仍然有效；对于新物品，模型更多依赖内容特征。

实际模型不一定真的用固定加权求和，但可以通过以下方式实现类似效果：

- 降低 ID Embedding 维度；
- 对 ID 特征增加 Dropout；
- 训练时随机屏蔽物品 ID；
- 增强类目、关键词和多模态特征；
- 对新老物品采用不同的特征融合权重。

这种改造可以避免模型过度“记忆”热门老物品。

---

# 6. 为什么训练时要模拟冷启动

如果训练数据中所有物品都有完整 ID Embedding，而线上新物品却使用 Default Embedding，训练和推理之间就会出现差异。

模型在训练阶段可能形成依赖：

```text
只要看物品 ID，就能判断这个物品是否受欢迎
```

但线上遇到新物品时，ID 特征突然失效，模型效果就会明显下降。

因此，训练时可以随机屏蔽物品 ID：

```text
一定概率使用真实 item_id_embedding
一定概率替换为 default_embedding
```

伪代码：

```cpp
Embedding build_item_id_embedding(
    ItemId item_id,
    bool training,
    double mask_probability) {

    if (training && random_double() < mask_probability) {
        return default_embedding;
    }

    auto iter = embedding_table.find(item_id);
    if (iter == embedding_table.end()) {
        return default_embedding;
    }

    return iter->second;
}
```

这相当于提前告诉模型：

> 有时你不能依赖物品 ID，需要学会从类目、关键词和内容中理解物品。

---

# 7. Default Embedding 的局限

Default Embedding 解决的是：

> 新物品无法进入双塔模型计算流程的问题。

但它并不能自动解决：

> 新物品应该推荐给哪些用户的问题。

如果两个新物品都使用相同的 Default Embedding，而且它们的内容特征也比较弱，那么生成的向量可能非常相似。

因此，Default Embedding 通常只是兜底方案，还需要配合：

- 类目特征；
- 关键词特征；
- 作者特征；
- 文本语义向量；
- 图片或视频多模态向量；
- 类目召回；
- 关键词召回；
- 冷启动专属流量池。

---

# 8. 类目召回

## 8.1 什么是类目召回

类目召回的基本思想是：

> 用户过去喜欢什么类目的内容，就从这些类目中召回新物品。

例如，一个用户最近经常浏览：

```text
C++：40%
Rust：30%
Linux：20%
其他：10%
```

那么系统可以从以下新物品池中召回：

```text
C++ 类目新内容
Rust 类目新内容
Linux 类目新内容
```

可以将其理解为：

> 系统虽然不知道用户是否喜欢某一篇具体的新文章，但知道用户大概率喜欢这个领域。

---

## 8.2 类目召回的基本流程

```text
用户历史行为
    ↓
统计用户偏好的类目
    ↓
选出 TopN 类目
    ↓
从对应类目的新物品池中取候选
    ↓
按照发布时间、质量分等排序
    ↓
返回召回结果
```

例如：

```text
用户喜欢：
游戏、数码、编程

新物品池：
游戏类新视频
数码类新商品
编程类新文章

系统分别召回一部分，再合并
```

---

## 8.3 用户类目兴趣如何计算

一个简单做法是对用户历史行为加权统计。

例如：

```text
点击          +1
长时间阅读    +2
点赞          +3
收藏          +4
负反馈        -5
```

伪代码：

```cpp
std::unordered_map<CategoryId, double>
build_user_category_profile(const std::vector<UserBehavior>& behaviors) {
    std::unordered_map<CategoryId, double> scores;

    for (const auto& behavior : behaviors) {
        double weight = 0.0;

        switch (behavior.type) {
            case BehaviorType::Click:
                weight = 1.0;
                break;
            case BehaviorType::LongView:
                weight = 2.0;
                break;
            case BehaviorType::Like:
                weight = 3.0;
                break;
            case BehaviorType::Favorite:
                weight = 4.0;
                break;
            case BehaviorType::Negative:
                weight = -5.0;
                break;
        }

        scores[behavior.category_id] += weight;
    }

    return scores;
}
```

真实业务中还会加入时间衰减：

```text
越近的行为，权重越高
越久以前的行为，权重越低
```

例如：

```text
最终权重 = 行为权重 × 时间衰减系数
```

---

## 8.4 类目召回索引

在线服务中，通常不会每次遍历所有新物品，而是提前建立倒排索引：

```text
category_id → 该类目下的新物品列表
```

例如：

```text
C++   → [item1, item5, item9]
Rust  → [item2, item6]
Linux → [item3, item7, item8]
```

在线请求时：

```cpp
std::vector<ItemId> recall_by_category(
    const std::vector<CategoryId>& top_categories,
    std::size_t per_category_limit) {

    std::vector<ItemId> result;

    for (CategoryId category_id : top_categories) {
        const auto& items = category_index.get(category_id);

        std::size_t count = 0;
        for (ItemId item_id : items) {
            if (count >= per_category_limit) {
                break;
            }

            result.push_back(item_id);
            ++count;
        }
    }

    return result;
}
```

类目索引中的物品通常会按照以下方式预排序：

- 发布时间；
- 初始质量分；
- 作者质量分；
- 当前冷启动阶段；
- 已获得曝光量；
- 安全审核结果。

---

## 8.5 类目召回的优缺点

优点：

- 实现简单；
- 召回速度快；
- 可解释性强；
- 新物品一发布就能进入类目池；
- 不依赖新物品历史行为。

缺点：

- 类目粒度通常较粗；
- 同一类目内部差异可能很大；
- 个性化能力有限；
- 容易反复推荐同一类内容；
- 依赖类目标注质量。

例如，“数码”这个类目可能同时包含：

- 手机；
- 相机；
- 键盘；
- 显示器；
- 路由器。

用户喜欢键盘，不一定喜欢所有数码产品。

---

# 9. 关键词召回

## 9.1 什么是关键词召回

关键词召回的基本思想是：

> 根据用户历史感兴趣的关键词，从包含相同或相似关键词的新物品中召回候选。

例如，用户近期经常浏览：

```text
C++
Rust
Tokio
异步编程
Linux
```

新发布了一篇文章：

```text
标题：Tokio 中 async/await 的执行原理
关键词：Tokio、Rust、异步编程
```

即使这篇文章没有任何点击数据，也可以通过关键词匹配召回给该用户。

---

## 9.2 关键词召回基本流程

```text
用户历史行为
    ↓
提取用户兴趣关键词
    ↓
构建用户关键词画像
    ↓
查询关键词倒排索引
    ↓
得到对应的新物品
    ↓
合并、去重和截断
```

倒排索引形式如下：

```text
Rust      → [item1, item4, item8]
Tokio     → [item1, item5]
Linux     → [item2, item7]
C++       → [item3, item6]
```

用户兴趣关键词是：

```text
Rust、Tokio
```

那么就可以召回：

```text
item1、item4、item8、item5
```

其中 `item1` 同时匹配两个关键词，可以获得更高分数。

---

## 9.3 关键词从哪里来

物品关键词可以来自：

- 作者手动填写的标签；
- 标题分词；
- 正文分词；
- 商品属性；
- 搜索词；
- NLP 关键词提取模型；
- 大语言模型生成；
- 图片或视频内容识别。

用户关键词画像则可以来自：

- 用户点击过的物品关键词；
- 用户收藏过的物品关键词；
- 用户搜索过的词；
- 用户停留时间较长的内容；
- 用户主动关注的话题。

---

## 9.4 简单关键词召回评分

最简单的评分方式是统计匹配关键词数量：

```text
score(item)
    =
用户兴趣关键词与物品关键词的交集大小
```

例如：

```text
用户关键词：Rust、Tokio、Linux

物品 A：Rust、Tokio
物品 B：Linux、网络
物品 C：Python、AI

A 匹配 2 个
B 匹配 1 个
C 匹配 0 个
```

因此：

```text
A 的召回分数 > B 的召回分数 > C
```

伪代码：

```cpp
double keyword_match_score(
    const std::unordered_map<std::string, double>& user_keywords,
    const std::vector<std::string>& item_keywords) {

    double score = 0.0;

    for (const auto& keyword : item_keywords) {
        auto iter = user_keywords.find(keyword);

        if (iter != user_keywords.end()) {
            score += iter->second;
        }
    }

    return score;
}
```

这里 `user_keywords` 中的权重可以表示用户对某个关键词的兴趣强度。

---

## 9.5 更合理的关键词权重

不是所有关键词都同样重要。

例如：

```text
“视频”
“推荐”
“内容”
```

这些词出现得非常频繁，区分能力较弱。

而：

```text
Tokio
HNSW
MMoE
io_uring
```

更能表达具体兴趣。

因此，关键词召回通常会考虑类似 TF-IDF 的思想：

```text
关键词越稀有，区分能力越强
关键词越常见，权重越低
```

简单公式：

```text
关键词得分
    =
用户兴趣权重
× 关键词区分度
× 时间衰减
```

还可以加入：

- 标题关键词加权；
- 正文关键词降权；
- 用户搜索词加权；
- 收藏行为加权；
- 最近兴趣加权；
- 负反馈关键词过滤。

---

# 10. 类目召回与关键词召回的区别

| 对比维度 | 类目召回 | 关键词召回 |
|---|---|---|
| 匹配粒度 | 较粗 | 较细 |
| 实现难度 | 很低 | 较低 |
| 召回速度 | 很快 | 很快 |
| 可解释性 | 很强 | 很强 |
| 个性化能力 | 一般 | 相对更强 |
| 对标注质量依赖 | 依赖类目 | 依赖关键词 |
| 新物品适用性 | 很好 | 很好 |
| 主要问题 | 类目过粗 | 关键词噪声较多 |

可以简单理解为：

```text
类目召回：
用户喜欢“编程”

关键词召回：
用户喜欢“Rust、Tokio、异步编程”
```

因此，关键词召回通常比类目召回更精细，但也更容易受到错误关键词和低质量标签的影响。

---

# 11. 两种召回方式如何组合

类目召回和关键词召回通常不会互相替代，而是同时作为独立召回通道。

```text
用户请求
   ├── 双塔向量召回
   ├── 类目召回
   ├── 关键词召回
   ├── 作者召回
   └── 热门兜底召回
            ↓
        候选集合并
            ↓
          去重
            ↓
       粗排 / 精排
            ↓
          重排
```

例如：

```text
双塔召回：200 条
类目召回：100 条
关键词召回：100 条
热门兜底：50 条
```

合并后去重，再交给排序层。

实际数量需要根据业务规模、延迟预算和各路召回质量配置。

# 12. 简单的多路召回实现

```cpp
struct RecallCandidate {
    ItemId item_id;
    double score;
    std::string source;
};

std::vector<RecallCandidate> cold_start_recall(
    const UserProfile& user,
    std::size_t limit) {

    std::vector<RecallCandidate> candidates;

    auto tower_items = two_tower_recall(user, 200);
    auto category_items = category_recall(user, 100);
    auto keyword_items = keyword_recall(user, 100);

    candidates.insert(
        candidates.end(),
        tower_items.begin(),
        tower_items.end());

    candidates.insert(
        candidates.end(),
        category_items.begin(),
        category_items.end());

    candidates.insert(
        candidates.end(),
        keyword_items.begin(),
        keyword_items.end());

    std::unordered_map<ItemId, RecallCandidate> deduplicated;

    for (const auto& candidate : candidates) {
        auto iter = deduplicated.find(candidate.item_id);

        if (iter == deduplicated.end() ||
            candidate.score > iter->second.score) {
            deduplicated[candidate.item_id] = candidate;
        }
    }

    std::vector<RecallCandidate> result;
    result.reserve(deduplicated.size());

    for (auto& [item_id, candidate] : deduplicated) {
        result.push_back(std::move(candidate));
    }

    std::sort(
        result.begin(),
        result.end(),
        [](const auto& lhs, const auto& rhs) {
            return lhs.score > rhs.score;
        });

    if (result.size() > limit) {
        result.resize(limit);
    }

    return result;
}
```

需要注意，不同召回通道的原始分数含义不同：

```text
双塔召回分数：向量相似度
类目召回分数：类目兴趣权重
关键词召回分数：关键词匹配权重
```

因此，真实系统通常不会直接比较这些原始分数，而是：

- 各路单独截断；
- 进行分数归一化；
- 为不同通道设置权重；
- 或直接交给粗排模型重新打分。

# 13. 新物品索引如何更新

物品冷启动要求新物品发布后能够尽快进入召回系统。

因此，新物品发布流程通常是：

```text
物品发布
    ↓
审核与质量检查
    ↓
提取类目和关键词
    ↓
生成内容向量
    ↓
写入类目倒排索引
    ↓
写入关键词倒排索引
    ↓
写入向量索引
    ↓
进入冷启动候选池
```

这里有一个重要的工程要求：

> 新物品索引更新必须足够及时。

如果索引一天才更新一次，那么用户当天发布的新内容可能第二天才能被召回，这种冷启动体验通常很差。

工业系统往往会采用：

- 消息队列传递新物品事件；
- 实时或分钟级特征处理；
- 增量更新倒排索引；
- 增量插入 ANN 向量索引；
- KV 存储新物品元数据。

---

# 14. 冷启动召回中的常见约束

新物品召回不能只看相关性，还需要增加一些业务限制。

## 14.1 曝光上限

防止某个新物品在质量还没有验证时获得过多流量：

```text
当前曝光量 < 冷启动阶段曝光上限
```

---

## 14.2 发布时间限制

类目和关键词召回池通常只保留最近发布的物品：

```text
发布时间在最近 24 小时内
或
发布时间在最近 7 天内
```

具体时间窗口由业务决定。

---

## 14.3 质量门槛

新物品进入冷启动池前，可以先检查：

- 内容是否完整；
- 图片或视频是否清晰；
- 是否存在违规内容；
- 是否重复发布；
- 作者是否可信；
- 标题是否存在欺骗性。

---

## 14.4 去重和已看过滤

召回结果还需要过滤：

- 用户已经看过的物品；
- 重复或高度相似内容；
- 用户明确不喜欢的作者；
- 用户屏蔽的类目；
- 已达到曝光上限的物品。

在服务端工程中，可以使用：

- Bloom Filter；
- Redis Set；
- 用户行为 KV；
- 本地缓存；
- 近线生成的已看列表。

---

# 15. 一套简单实用的冷启动召回方案

对于第一版工业推荐系统，可以采用以下结构：

```text
第一路：改造后的双塔召回
- 未知物品 ID 使用 Default Embedding
- 加入类目、关键词、作者和文本向量

第二路：类目召回
- 根据用户 Top 类目兴趣
- 从对应新物品池中取候选

第三路：关键词召回
- 根据用户 Top 兴趣关键词
- 查询关键词倒排索引

第四路：热门新物品兜底
- 当召回不足时补充近期表现较好的新物品
```

整体流程：

```text
用户请求
    ↓
获取用户画像
    ↓
并行执行多路召回
    ↓
合并和去重
    ↓
过滤已看、违规和超曝光物品
    ↓
粗排重新打分
    ↓
精排预测点击、时长和互动
    ↓
重排控制新物品比例与多样性
```

这种方案不复杂，但已经能够较完整地解决第一阶段物品冷启动问题。

# 16. 如何理解三种方法的定位

## 16.1 Default Embedding

解决：

> 新物品 ID 没有训练过，如何进入双塔模型？

它是一种模型层面的兼容和兜底机制。

---

## 16.2 类目召回

解决：

> 虽然不知道用户是否喜欢这个具体新物品，但可以根据大类兴趣先做匹配。

它是一种粗粒度、稳定的召回方式。

---

## 16.3 关键词召回

解决：

> 如何利用更细粒度的内容语义，将新物品匹配给兴趣相近的用户？

它是一种比类目更细的可解释召回方式。

---

# 17. 注意事项

## 17.1 不要让双塔模型过度依赖物品 ID

如果模型主要记忆物品 ID，老物品效果可能很好，但新物品效果会很差。

因此，训练时应加强内容特征，并适当模拟 ID 缺失。

---

## 17.2 不要把 Default Embedding 当成完整解决方案

Default Embedding 只是让新物品能够被模型处理。

真正区分新物品的还是：

- 类目；
- 关键词；
- 作者；
- 文本；
- 图片；
- 视频；
- 多模态语义。

---

## 17.3 类目召回不要过于单一

如果长期只按照用户最喜欢的一个类目召回，会造成信息茧房。

可以从多个类目按比例召回，并保留少量探索流量。

---

## 17.4 关键词需要清洗

需要过滤：

- 停用词；
- 过于常见的词；
- 广告词；
- 作弊标签；
- 与正文不一致的标签；
- 低置信度自动标签。

---

## 17.5 新物品流量要逐步放大

新物品刚进入系统时，数据置信度很低。

合理方式是：

```text
小流量测试
    ↓
反馈良好
    ↓
逐渐扩大流量
```

而不是一开始就给大量曝光。

---

# 18. 总结

物品冷启动阶段最大的困难是：

> 新物品没有历史行为，也没有可靠的 ID Embedding。

双塔模型可以通过以下方式改造：

```text
未知 item_id
    ↓
使用 Default Embedding
    ↓
结合类目、关键词、作者和内容特征
    ↓
生成可用于向量召回的 item_embedding
```

同时，为了让新物品能够稳定进入候选集，还可以增加两条简单召回通道：

```text
类目召回：
根据用户喜欢的大类，从对应类目新物品池中召回。

关键词召回：
根据用户感兴趣的细粒度关键词，从关键词倒排索引中召回。
```

三种方式的定位可以概括为：

```text
Default Embedding：解决模型能不能处理新物品
类目召回：解决新物品的大方向匹配
关键词召回：解决新物品的细粒度兴趣匹配
```

对于第一版物品冷启动系统，这套方案具有明显优势：

- 实现成本较低；
- 在线性能稳定；
- 可解释性较强；
- 新物品能够快速进入召回池；
- 可以在后续逐步升级为内容向量召回、多模态召回和实时反馈放量机制。
