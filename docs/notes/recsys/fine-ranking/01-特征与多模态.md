# 推荐系统排序层学习笔记：特征、多模态建模与分数融合

## 1. 整体认识

排序层接收召回阶段产生的候选物品，综合用户、物品和当前场景信息，预测用户可能产生的行为，然后为每个候选计算统一排序分数。

```text
召回候选
   ↓
构造用户、物品、场景和行为序列特征
   ↓
粗排 / 精排模型
   ↓
输出多个预估目标
   ├─ pCTR
   ├─ pCVR
   ├─ 有效播放概率
   ├─ 预估观看时长
   ├─ 完播概率
   ├─ 点赞概率
   └─ 负反馈概率
   ↓
预估分数融合
   ↓
Top-K 排序
   ↓
重排与最终曝光
```

排序模型本质上是在回答：

> 当前用户在当前场景下，对当前候选产生点击、观看、互动或转化行为的可能性有多大？

---

# 2. 排序模型常用特征

完整的精排样本通常由以下部分构成：

```text
用户画像
+ 用户统计
+ 用户行为序列
+ 物品画像
+ 物品统计
+ 场景特征
+ 用户与物品交叉特征
```

## 2.1 用户画像特征

用户画像描述用户较稳定的属性和长期兴趣，例如：

```text
用户 ID
年龄、地域
注册时长
设备偏好
长期兴趣类目
常看作者
消费能力
活跃等级
```

它主要回答：

> 这个用户整体上是什么类型的人，长期喜欢什么？

画像既可能来自注册信息，也可能由长期行为聚合得到。

## 2.2 物品画像特征

物品画像描述候选内容本身是什么，例如：

```text
物品 ID、作者 ID
类目、标签
发布时间
标题、正文
图片、视频
文本 Embedding
图片 Embedding
视频 Embedding
内容质量分
视频长度
```

它主要回答：

> 当前候选内容是什么，表达了什么语义？

## 2.3 用户统计特征

用户统计特征描述用户在不同时间窗口内的行为强度：

```text
最近 1 小时点击次数
最近 1 天曝光次数
最近 7 天历史 CTR
平均观看时长
点赞率、收藏率
各类目点击占比
最近一次访问时间
```

常用时间窗口：

```text
10 分钟、1 小时、1 天、7 天、30 天
```

短窗口反映即时意图，长窗口反映稳定偏好。

## 2.4 物品统计特征

物品统计特征描述内容在平台上的历史表现：

```text
曝光次数
点击次数与 CTR
平均观看时长
完播率
点赞率、收藏率、分享率
负反馈率
近期热度和增长速度
```

新内容统计量通常不稳定。例如曝光一次、点击一次会得到 100% CTR，因此工业中会使用：

- 平滑和贝叶斯估计；
- 时间衰减；
- 分桶；
- 最小曝光门槛；
- 冷启动保护。

## 2.5 场景特征

场景特征描述本次推荐发生的环境：

```text
当前时间和星期
设备与操作系统
网络类型
推荐入口和页面
列表位置
用户所在地域
当前会话长度
距离上次行为的时间
```

同一用户在工作日上午、晚上娱乐时间、首页推荐和搜索页面中，兴趣表达可能完全不同。

## 2.6 用户行为序列

现代精排模型通常会输入最近的点击、播放和互动序列：

```text
物品 Embedding
行为类型
行为时间
观看时长
完播率
是否点赞
是否快速划走
```

单条行为可以表示为：

\[
Behavior_j=[
ItemEmbedding,\ BehaviorType,\ Timestamp,\ WatchTime
]
\]

DIN、Transformer 等模型会根据当前候选，为不同历史行为分配不同权重：

\[
h_u(i)=Attention(candidate_i,history)
\]

因此用户兴趣不是完全固定的，而是可以针对当前候选动态生成。

## 2.7 交叉特征

交叉特征直接描述用户与候选的匹配关系：

```text
用户是否喜欢候选类目
用户是否看过候选作者
候选是否与近期行为相似
用户消费区间是否匹配物品价格
用户向量与物品向量的相似度
```

可以抽象为：

\[
CrossFeature=f(User,Item,Context)
\]

DeepFM、DCN、DIN 和 Transformer 等模型的重要作用，就是自动学习复杂的特征交互。

# 3. 视频播放行为建模

## 3.1 为什么不能只看点击率

短视频通常自动播放，用户不一定需要点击，所以 CTR 无法完整表示兴趣。视频排序更关注：

```text
是否有效播放
观看时长
播放进度
是否完播
是否重复播放
是否快速划走
点赞、评论、关注、分享
负反馈
```

因此视频排序一般采用多任务模型。

## 3.2 常见标签

假设视频总时长为 \(d\)，实际观看时长为 \(t\)。

### 观看时长

\[
y_{watch}=t
\]

观看时长通常呈长尾分布，可先变换：

\[
y_{watch}=\log(1+t)
\]

再使用 MSE 或 Huber Loss。

### 完播率

\[
CompletionRate=\min\left(rac{t}{d},1
ight)
\]

也可以将完播定义为二分类任务，并使用 BCE。

### 有效播放

有效播放用于区分真正消费与立即划走，通常定义为：

```text
观看时长超过阈值
或
观看进度超过阈值
```

具体阈值通常随视频长度变化。

### 快速划走与深度互动

快速划走是重要负反馈；点赞、评论、分享、关注、重播属于更深层的正反馈。

多任务损失可以写成：

\[
L=
\lambda_1L_{play}
+\lambda_2L_{watch}
+\lambda_3L_{finish}
+\lambda_4L_{like}
+\lambda_5L_{negative}
\]

底层模型可以采用 Shared-Bottom、MMoE 或 PLE。

# 4. 视频时长偏差

直接优化绝对观看时长会天然偏向长视频。

例如：

```text
视频 A：总长 10 秒，观看 10 秒
视频 B：总长 300 秒，观看 40 秒
```

视频 B 的绝对时长更高，但视频 A 被完整看完。因此观看时长不能单独代表兴趣。

常见处理方法如下。

## 4.1 同时预测时长和完播率

\[
Score=
lpha\hat{WatchTime}
+eta pFinish
+\gamma pLike
-\delta pSkip
\]

这样兼顾绝对消费深度与相对完成度。

## 4.2 按视频长度分桶

例如：

```text
0～10 秒
10～30 秒
30～60 秒
1～3 分钟
3 分钟以上
```

在同长度视频内部进行归一化：

\[
NormalizedWatchTime=
rac{t-\mu_{bucket}}{\sigma_{bucket}}
\]

## 4.3 条件观看时长

把观看过程拆成：

\[
P(	ext{有效播放})
	imes
E[	ext{WatchTime}\mid	ext{有效播放}]
\]

即先预测用户愿不愿意看，再预测愿意看多久。

## 4.4 处理噪声观看

自动播放、手机被放置一旁、用户未及时划走，都可能产生虚假的观看时间。因此还应结合：

```text
前后台状态
是否静音
播放进度
互动行为
快速划走
重复播放
```

# 5. 视频排序训练样本

通常以一次曝光作为一条训练样本：

```text
用户特征
+ 候选视频特征
+ 当前场景
+ 用户历史序列
+ 曝光后的播放和互动结果
```

示意结构：

```cpp
struct VideoRankSample {
    UserFeatures user;
    VideoFeatures video;
    ContextFeatures context;
    HistorySequence history;

    bool effective_play;
    float watch_seconds;
    bool finished;
    bool liked;
    bool shared;
    bool negative_feedback;
};
```

训练时要注意：

1. 只能使用曝光发生时已经可获得的特征；
2. 避免未来信息泄漏；
3. 负样本优先来自已曝光但未有效消费的内容；
4. 记录曝光位置、场景和召回来源；
5. 对点赞、分享、转化等稀疏任务进行重采样或 Loss 加权；
6. 训练日志由旧推荐策略产生，天然存在曝光选择偏差。

# 6. 图文内容建模

图文建模主要回答：

> 候选内容的图片和文字分别表达了什么，它们是否一致？

输入可能包括：

```text
封面图和正文图片
标题和正文
标签和类目
OCR 文本
作者信息
```

图片和文本分别经过编码器：

\[
e_{image}=ImageEncoder(image)
\]

\[
e_{text}=TextEncoder(text)
\]

常见编码器：

```text
图片：CNN、ResNet、ViT
文本：BERT、Sentence-BERT、Transformer
图文联合：CLIP 类模型
```

---

# 7. 常见图文融合方式

## 7.1 后融合

先离线计算图片与文本 Embedding，在线排序时进行拼接：

\[
e_{item}=Concat(e_{id},e_{image},e_{text},e_{category})
\]

这是工业中较实用的方式：

```text
物品发布
   ↓
离线图文 Encoder
   ↓
生成固定维度 Embedding
   ↓
写入 Feature Store
   ↓
在线精排批量读取
```

优点是在线延迟低、方便缓存和批量推理。

## 7.2 门控融合

让模型动态决定当前物品更依赖图片还是文本：

\[
g=Sigmoid(W[e_{image};e_{text}])
\]

\[
e_{content}=g\odot e_{image}+(1-g)\odot e_{text}
\]

例如服饰内容可能更依赖图片，技术文章可能更依赖文字。

## 7.3 深度交互融合

使用 Cross-Attention 或多模态 Transformer，让图像 Token 和文本 Token 进行细粒度交互：

```text
图像 Patch Token ─┐
                  ├─ Cross Attention
文本 Token ───────┘
```

表达能力更强，但计算成本也更高，通常更适合离线处理或较小候选规模。

# 8. 图文模型的训练流程

## 8.1 图文对比预训练

给定一个 Batch 的图文对，正确配对作为正样本，其他组合作为负样本：

\[
s_{ij}=
rac{e_{image_i}^{T}e_{text_j}}{	au}
\]

训练目标：

```text
正确图文靠近
错误图文远离
```

## 8.2 领域数据适配

使用平台自身数据继续训练：

```text
商品图片 + 标题
视频封面 + 标题
文章配图 + 正文
用户生成内容 + 标签
```

还会构造 Hard Negative，例如同类目但语义不匹配的图文对。

## 8.3 推荐任务微调

图文语义一致不代表用户一定喜欢，因此还要结合点击、观看、转化等排序目标：

\[
L=
L_{ranking}
+lpha L_{image-text}
+eta L_{content-id}
\]

其中：

```text
Lranking：推荐行为目标
Limage-text：图文语义对齐
Lcontent-id：内容表示与 ID 表示对齐
```

# 9. 为什么同时保留 ID 和图文特征

ID Embedding 主要学习协同信号：

```text
哪些用户点击过该物品
它常与哪些物品一起被消费
```

图文 Embedding 描述物品本身：

```text
内容讲了什么
图片展示了什么
图文语义是什么
```

| 特征 | 优势 | 局限 |
|---|---|---|
| ID Embedding | 协同信号强 | 新物品缺少行为 |
| 图文 Embedding | 新物品可立即生成 | 未必天然符合推荐目标 |
| 统计特征 | 稳定、可解释 | 表达能力有限 |

常见物品表示为：

\[
e_{item}=Fusion(e_{id},e_{image},e_{text},e_{statistics})
\]

图文特征尤其适合缓解新物品冷启动。

# 10. 图文建模的工程措施

常见措施包括：

- 使用 Mask 和默认向量处理模态缺失；
- 使用 Modality Dropout，避免模型过度依赖单一模态；
- 过滤空标题、低清图片、水印、重复图片和 OCR 噪声；
- 将内容表示压缩为固定维度 Embedding；
- 使用蒸馏把大模型能力迁移到轻量模型；
- 使用 FP16 或 INT8 降低存储和传输成本。

大型图文模型通常放在离线或近线链路，而不是直接运行在每个在线排序请求中。

# 11. 预估分数融合

多任务模型会输出多个目标：

```text
pCTR
pCVR
pLike
pFinish
WatchTime
pNegative
```

最终排序需要一个统一分数：

\[
Score=F(pCTR,pCVR,pLike,pFinish,WatchTime,pNegative)
\]

分数融合的本质是：

> 将多个用户行为预测和业务价值转换为一个统一排序目标。

## 11.1 线性融合

\[
Score=
w_1pCTR
+w_2pCVR
+w_3pLike
+w_4WatchTime
-w_5pNegative
\]

优点是简单、可解释、容易在线调参。

```cpp
float fuse_score(
    const Prediction& p,
    const FusionWeights& w
) {
    return w.ctr * p.pctr
         + w.cvr * p.pcvr
         + w.like * p.like_prob
         + w.finish * p.finish_prob
         + w.watch * p.watch_time
         - w.negative * p.negative_prob;
}
```

## 11.2 乘法融合

适合点击—转化—价值这样的漏斗：

\[
ExpectedGMV=pCTR	imes pCVR	imes Price
\]

广告中常见：

\[
eCPM=1000	imes pCTR	imes Bid
\]

## 11.3 加乘混合

\[
Score=
pCTR^lpha
	imes(1+eta pLike)
	imes(1+\gamma pFinish)
-\lambda pNegative
\]

既能表达漏斗关系，也能加入互动与负反馈。

## 11.4 学习式融合

将多个预估值再次输入一个模型：

\[
Score=MLP(pCTR,pCVR,pLike,WatchTime,Context)
\]

表达能力更强，但可解释性和可控性较差。

# 12. 融合前的归一化与校准

不同目标的量纲可能完全不同：

```text
pCTR = 0.08
pLike = 0.02
WatchTime = 35 秒
```

直接相加会让观看时长完全主导分数。

因此融合前通常进行：

- 归一化；
- 标准化；
- 对数变换；
- 分桶；
- 截断；
- 概率校准。

例如：

\[
WatchScore=\log(1+WatchTime)
\]

或：

\[
WatchScore=rac{\min(WatchTime,120)}{120}
\]

概率校准的目标是：模型输出 0.1 时，真实发生率尽量接近 10%。否则多个任务的融合比例会失真。

# 13. 分数融合中的常见问题

## 13.1 目标冲突

```text
提高 CTR 可能降低 CVR
提高观看时长可能偏向低质量长内容
提高转化可能降低流量规模
```

因此融合本质上是业务目标之间的权衡。

## 13.2 分数尺度漂移

模型升级后，AUC 可能提高，但输出均值也可能从 0.08 变成 0.20，破坏原有融合公式。

需要监控：

```text
输出均值和分位数
概率校准
Top-K 重合率
新旧模型排序差异
```

## 13.3 短期指标与长期价值冲突

只优化点击和时长，可能损害：

```text
次日留存
用户满意度
内容多样性
创作者生态
```

因此线上实验一般采用：

```text
核心指标 + 护栏指标
```

---

# 14. 分数融合与重排的区别

分数融合关注单个候选：

```text
这个候选有多值得推荐？
```

重排关注整个列表：

```text
最终列表整体是否合理？
```

分数融合考虑点击、观看、转化和负反馈；重排还会处理：

```text
多样性
作者打散
类目打散
去重
新内容扶持
广告插入
业务配额
```

可以记忆为：

```text
分数融合：计算单物品价值
重排：优化整体列表结构
```

# 15. C++ 在线排序服务中的实现位置

重型图像、文本和视频编码通常放在离线或近线链路：

```text
物品发布
   ↓
图片 / 文本 / OCR / ASR 处理
   ↓
多模态模型
   ↓
生成固定维度 Embedding
   ↓
写入 Feature Store
```

在线 C++ 服务主要负责：

```text
批量读取用户和物品特征
读取图文 Embedding
读取用户播放历史
构造连续 Tensor
调用 ONNX Runtime / TensorRT
解析多任务输出
执行分数融合
选择 Top-K
```

简化伪代码：

```cpp
auto item_features =
    feature_store.batch_get(candidate_ids);

Tensor input(candidate_ids.size(), feature_dim);

for (std::size_t i = 0; i < candidate_ids.size(); ++i) {
    fill_row(
        input.row(i),
        user_features,
        user_history,
        item_features[i],
        context_features
    );
}

auto predictions = rank_model.predict(input);

for (std::size_t i = 0; i < predictions.size(); ++i) {
    scores[i] =
        config.play_weight
            * predictions[i].play_prob
        + config.watch_weight
            * predictions[i].normalized_watch_time
        + config.finish_weight
            * predictions[i].finish_prob
        + config.like_weight
            * predictions[i].like_prob
        - config.negative_weight
            * predictions[i].negative_prob;
}
```

# 17. 最终记忆

排序模型常用特征：

```text
用户特征
+ 物品特征
+ 行为序列
+ 统计特征
+ 场景特征
+ 交叉特征
```

视频播放建模主要解决：

```text
用户愿不愿意看
愿意看多久
是否真正看完
是否深度互动
是否快速划走
```

图文建模主要解决：

```text
内容是什么
```
