# 物品冷启动中的聚类召回与 Look-Alike 召回

## 1. 为什么冷启动需要特殊召回

新物品刚发布时，通常缺少点击、点赞、收藏、购买、播放时长等行为数据。

这会让传统协同过滤遇到困难：

- **ItemCF** 依赖物品之间的用户行为共现，新物品没有共现数据；
- **UserCF** 依赖相似用户消费过的物品，新物品还没有被用户消费。

因此，冷启动召回不会只依赖新物品自身的历史行为，而是利用：

- 类目、关键词、文本、图片等内容特征；
- 作者及作者历史受众；
- 相似老物品积累的用户行为；
- 少量试探流量产生的初始反馈。

聚类召回和 Look-Alike 召回就是两种常见方法。

---

## 2. 聚类召回

### 2.1 基本原理

聚类召回先按照特征相似性，把物品划分为若干内容群组，再把新物品推荐给对相应群组感兴趣的用户。

例如，系统中存在以下内容簇：

```text
聚类 1：C++ 服务端
聚类 2：Rust 基础语法
聚类 3：Rust 异步编程
聚类 4：Linux 网络编程
```

新文章《Tokio 中 Waker 的工作原理》虽然没有点击数据，但可以根据标题、正文、关键词和文本向量，被划入“Rust 异步编程”聚类。

系统随后将它召回给过去经常消费该聚类内容的用户。

### 2.2 工作流程

```text
已有物品
  ↓
提取类目、关键词、文本、图片等特征
  ↓
执行聚类，得到若干物品簇
  ↓
统计每个用户感兴趣的物品簇
```

新物品发布后：

```text
新物品
  ↓
生成内容 Embedding
  ↓
找到距离最近的聚类中心
  ↓
写入对应聚类的新物品池
  ↓
召回给对该聚类感兴趣的用户
```

简化伪代码：

```cpp
std::vector<ItemId> cluster_recall(
    const UserProfile& user,
    std::size_t limit) {

    auto clusters = get_top_interested_clusters(user);

    std::vector<ItemId> result;
    for (ClusterId cluster_id : clusters) {
        auto items = cluster_index.get_new_items(cluster_id);
        result.insert(result.end(), items.begin(), items.end());
    }

    filter_seen_and_invalid_items(result);

    if (result.size() > limit) {
        result.resize(limit);
    }
    return result;
}
```

### 2.3 为什么适合冷启动

它不要求新物品已经积累用户行为，只要新物品具有内容特征，就可以被放入已有兴趣群体。

本质上是：

> 让新物品复用同一聚类中成熟物品已经积累的受众经验。

## 3. Look-Alike 召回

### 3.1 基本原理

Look-Alike 的含义是“相似人群扩展”：

> 先找到一小批可能喜欢新物品的种子用户，再寻找更多与种子用户相似的人。

例如，一篇新的 Tokio 文章可以先选择以下用户作为种子：

- 看过相似 Tokio 内容的用户；
- 收藏过 Rust 异步文章的用户；
- 关注该作者的用户；
- 第一轮试探曝光中产生高质量反馈的用户。

然后利用用户画像或用户 Embedding，在全量用户中搜索更多相似用户。

### 3.2 种子用户是什么

种子用户是围绕某个物品或业务目标挑选出来的一小批高相关用户。

它们是 Look-Alike 的参考样本，而不是用户的永久身份。

种子用户常见来源：

```text
相似老物品的高质量用户
作者的历史核心受众
相关类目或关键词的兴趣用户
首轮曝光中的点赞、收藏、长时消费用户
```

### 3.3 工作流程

```text
新物品
  ↓
选择高相关种子用户
  ↓
获取种子用户 Embedding
  ↓
加权聚合为一个或多个种子中心
  ↓
在用户 ANN 索引中搜索相似用户
  ↓
向扩展人群推荐新物品
  ↓
根据反馈决定继续放量或停止
```

简化伪代码：

```cpp
std::vector<UserId> look_alike_expand(
    const std::vector<UserId>& seed_users,
    std::size_t top_k) {

    Embedding center{};
    double total_weight = 0.0;

    for (UserId user_id : seed_users) {
        double weight = get_seed_quality_weight(user_id);
        center += get_user_embedding(user_id) * weight;
        total_weight += weight;
    }

    center /= total_weight;
    return user_ann_index.search(center, top_k);
}
```

真实系统通常会过滤误点击、异常用户和低质量种子，也可能使用多个中心，避免把不同兴趣人群简单平均。

### 3.4 为什么适合冷启动

Look-Alike 不要求新物品已经获得大规模行为，只需要一小批相对可靠的种子用户。

这些种子可以通过内容匹配、作者关系、相似老物品或首轮试探流量获得。

本质上是：

> 从少量潜在受众出发，把新物品扩展给更多相似用户。

## 4. 与协同过滤召回的区别

聚类召回、Look-Alike 与 UserCF、ItemCF 都利用了“相似性”，但相似性的来源和使用方向不同。

| 方法 | 核心问题 | 主要依据 | 输出 | 对新物品的要求 |
|---|---|---|---|---|
| UserCF | 相似用户还喜欢什么 | 用户行为重合 | 物品 | 新物品通常需要已有行为 |
| ItemCF | 哪些物品经常被共同消费 | 用户—物品共现 | 物品 | 新物品通常需要已有行为 |
| 聚类召回 | 新物品属于哪个兴趣群体 | 内容、类目、关键词、Embedding | 物品 | 可不依赖新物品行为 |
| Look-Alike | 还有哪些人像种子用户 | 用户画像、行为、Embedding | 用户人群 | 只需少量种子或内容规则 |

### 4.1 聚类召回与 ItemCF

ItemCF：

```text
很多用户同时消费过 A 和 B
  ↓
认为 A 与 B 相似
```

聚类召回：

```text
A 和 B 在内容、类目或向量上相似
  ↓
将它们放入同一个内容簇
```

新物品没有共现行为，因此很难进入 ItemCF；但只要有内容信息，就可以进入聚类召回。

### 4.2 Look-Alike 与 UserCF

UserCF：

```text
当前用户
  ↓
寻找行为相似用户
  ↓
推荐相似用户消费过的物品
```

Look-Alike：

```text
目标新物品
  ↓
确定一批种子用户
  ↓
寻找更多相似用户
  ↓
向扩展用户推荐目标物品
```

因此：

- UserCF 的起点是待推荐用户，最终寻找物品；
- Look-Alike 的起点是目标物品和种子人群，最终扩展用户。

---

## 5. 两种方法如何配合

聚类召回和 Look-Alike 可以形成一条完整的冷启动链路：

```text
新物品发布
  ↓
根据内容特征归入某个聚类
  ↓
召回一批对该聚类感兴趣的用户
  ↓
从正反馈用户中选出种子用户
  ↓
使用 Look-Alike 扩展更多相似用户
  ↓
根据后续反馈逐步放大流量
```

可以简单理解为：

- **聚类召回负责找到初始方向；**
- **Look-Alike 负责扩大潜在人群。**

---

## 6. 工业实践注意事项

### 聚类不要过粗

如果一个聚类同时包含大量差异明显的内容，召回准确率会下降。

### 种子质量比数量更重要

误点击、快速划走、作弊用户不应作为优质种子。应优先使用收藏、购买、完播、长时消费等强反馈。

### 避免简单平均全部种子

种子用户可能来自多个兴趣群体。可以先对种子分组，再分别执行 Look-Alike。

### 冷启动流量需要受控

召回结果仍需经过：

- 内容安全与质量过滤；
- 已看和重复内容过滤；
- 曝光上限控制；
- 粗排、精排与重排；
- 分阶段流量实验。

---

## 7. 总结

聚类召回和 Look-Alike 都通过“相似性迁移”解决新物品缺少行为的问题。

```text
聚类召回：
把新物品放入已有兴趣群体，
再推荐给对该群体感兴趣的用户。

Look-Alike：
找到少量高相关种子用户，
再扩展出更多相似用户。
```

它们与协同过滤最核心的区别是：

> UserCF 和 ItemCF 主要依赖目标对象已经形成的用户行为关系；聚类召回和 Look-Alike 则可以借助内容特征、相似老物品、群体归属和少量种子反馈，为新物品迁移已有经验。

快速记忆：

```text
UserCF：相似用户还喜欢什么？
ItemCF：哪些物品经常被共同消费？
聚类召回：新物品属于哪个兴趣群体？
Look-Alike：喜欢它的人还可能像哪些用户？
```
