# 推荐系统重排学习笔记：业务规则约束下的物品展示顺序

## 1. 为什么精排分数不能直接决定最终顺序？

经过召回、粗排和精排后，系统通常只剩下几十到几百个候选物品。精排模型已经为每个物品计算了点击率、播放时长、互动率、转化率等预估分数，因此最直接的做法是：

```text
按照精排分数降序排序
    ↓
截取前 Top-K
```

但真实推荐系统不能只考虑“单个物品的预测分数”。

例如，精排结果可能是：

```text
1. 篮球视频 A
2. 篮球视频 B
3. 篮球视频 C
4. 篮球视频 D
5. 手机广告
6. 手机广告
7. 同一作者的视频 E
```

即使这些物品的精排分数很高，直接展示仍可能出现：

- 同一类目连续出现；
- 同一作者重复曝光；
- 广告过于密集；
- 新作者没有曝光机会；
- 直播、广告、商品卡片集中在前几位；
- 已看、下架或不可用物品仍在候选中；
- 列表缺乏内容形式和主题多样性。

因此，重排阶段需要解决的问题不是：

> 哪个物品分数最高？

而是：

> 在当前已经排好的列表基础上，下一个位置放哪个物品，既能保持相关性，又能满足业务规则？

可以抽象为：

```text
final_score(user, item, position, selected_list, business_state)
```

其中不仅包含用户和物品，还包含：

- 当前展示位置；
- 已经选出的物品；
- 已使用的广告配额；
- 作者和类目曝光次数；
- 局部窗口中的重复情况；
- 运营和商业化规则。

---

# 2. 业务规则可以分成哪些类型？

业务规则不是同一种约束。工程实现时，首先要区分规则的性质，否则容易出现规则冲突和无法生成结果的问题。

## 2.1 硬过滤规则

这类物品无论分数多高，都不能进入最终列表。

常见规则：

```text
内容已下架
内容审核不通过
用户已经看过
商品已经售罄
当前地区不可展示
广告预算已经耗尽
作者被用户屏蔽
内容处于风控状态
```

这类规则应该尽早执行：

```text
精排候选
    ↓
硬过滤
    ↓
可参与重排的候选池
```

这样可以避免后续为无效物品计算复杂的重排分数。

---

## 2.2 位置约束

某类物品只能或不能出现在指定位置。

例如：

```text
前 3 位禁止广告
首位不能是直播
运营置顶内容必须出现在第 2 位
低质量探索内容不能进入前 5 位
```

判断形式通常是：

```cpp
bool can_place(const Item& item, std::size_t position);
```

---

## 2.3 频次约束

限制某种物品在整个 Top-K 中出现的次数。

例如：

```text
Top-10 最多出现 2 条广告
同一作者最多出现 2 条
同一店铺最多出现 3 个商品
Top-20 最多出现 4 条直播
```

通常需要维护计数器：

```cpp
std::unordered_map<AuthorId, int> author_count;
int ad_count;
int live_count;
```

---

## 2.4 间隔约束

要求相同类型的内容之间保持一定距离。

例如：

```text
两条广告之间至少间隔 3 条自然内容
同一作者不能连续出现
直播内容之间至少相隔 5 个位置
同品牌商品不能连续出现
```

这类规则需要记录最近一次出现的位置：

```cpp
std::optional<std::size_t> last_ad_position;
```

---

## 2.5 滑动窗口约束

限制最近一段局部列表中的内容重复度。

例如：

```text
最近 4 条中，同一类目最多出现 2 条
最近 6 条中，同一作者最多出现 1 条
最近 5 条中，直播最多出现 1 条
```

滑动窗口比全局限制更加符合信息流体验。

假设整个 Top-20 中允许有 8 条体育内容，但不希望连续出现：

```text
全局体育数量可以较多
局部窗口内必须打散
```

这与前面学习的滑动窗口 MMR 思想相似：用户对局部连续重复更敏感。

---

## 2.6 配额与保量规则

这类规则要求某类内容至少出现一定次数。

例如：

```text
Top-8 至少出现 1 条新作者内容
Top-10 至少出现 1 条本地内容
Top-20 至少出现 2 条探索内容
活动期间至少展示 1 个活动商品
```

它与“最多出现多少条”不同：

- 上限规则比较容易处理；
- 下限规则必须考虑后续是否还有足够位置完成配额。

一个简单做法是设置截止位置：

```text
如果前 7 位还没有新作者，
那么第 8 位必须选择新作者内容。
```

更通用的方式是进行可行性检查：

```text
剩余位置数 >= 尚未满足的最低配额
```

---

## 2.7 软规则

软规则不是“绝对不能违反”，而是通过加分或扣分影响顺序。

例如：

```text
新鲜内容加分
新作者内容适度加分
类目重复扣分
作者重复扣分
广告轻微降权
探索内容增加探索奖励
```

软规则通常表示为：

```text
adjusted_score
=
rank_score
+ bonus
- penalty
```

硬规则负责判断“能不能放”，软规则负责判断“应该优先放谁”。

---

# 3. 硬约束与软约束为什么必须分开？

假设有一条规则：

```text
同一类目不要连续出现。
```

它可以有两种实现。

## 3.1 作为硬约束

```cpp
if (previous.category == candidate.category) {
    return false;
}
```

结果是同类目内容绝对不能连续展示。

优点：

- 行为明确；
- 易于验证；
- 产品规则可以严格保证。

缺点：

- 候选不足时可能无法填满 Top-K；
- 可能把高相关内容过度后移；
- 多条规则组合后容易无解。

---

## 3.2 作为软约束

```cpp
if (previous.category == candidate.category) {
    score -= category_penalty;
}
```

结果是同类目内容可以连续出现，但优先级会下降。

优点：

- 更加灵活；
- 不容易出现无候选；
- 能够在相关性与体验之间平衡。

缺点：

- 无法绝对保证规则；
- 惩罚系数需要实验调参。

---

## 3.3 工业上的常见选择

一般遵循：

```text
安全、合规、库存、广告总量
    → 硬约束

多样性、新鲜度、探索、轻度打散
    → 软约束

产品明确承诺的频控
    → 硬约束或高优先级约束
```

例如：

```text
商品已售罄：绝对过滤
两条广告不能连续：硬约束
同类内容尽量分散：软惩罚
新作者适度曝光：奖励 + 最低配额
```

# 4. 业务规则下的常见排列方法

## 4.1 方法一：先排序，再顺序修补

最简单的方案：

1. 按精排分数降序排序；
2. 从头向后扫描；
3. 发现规则冲突时，与后面的可用候选交换。

示例：

```text
原始顺序：
体育 A、体育 B、体育 C、科技 A

规则：
同类目不能连续超过 2 条

修补后：
体育 A、体育 B、科技 A、体育 C
```

优点：

- 实现简单；
- 容易在旧系统中增加；
- 对原始精排顺序破坏较小。

缺点：

- 多条规则之间容易互相影响；
- 前一次交换可能破坏后面的规则；
- 难以处理最低配额；
- 规则越来越多时逻辑会变得混乱。

适合规则较少、仅需要简单打散的系统。

---

## 4.2 方法二：分桶后交替取物品

把物品按照类目、作者、内容类型等放入不同队列：

```text
体育队列
科技队列
影视队列
广告队列
直播队列
```

然后按照规则依次从不同队列取出物品。

例如：

```text
体育 → 科技 → 体育 → 影视 → 广告
```

优点：

- 对类目打散非常直观；
- 时间复杂度低；
- 容易控制每个桶的数量。

缺点：

- 多维约束难以同时处理；
- 一个物品可能同时属于多个规则维度；
- 容易牺牲精排分数；
- 需要设计复杂的桶优先级。

适合类目结构清晰、规则相对固定的场景。

---

## 4.3 方法三：逐位置贪心选择

这是在线重排中非常常见的思路。

对于第 `position` 个位置：

1. 遍历所有尚未选择的候选；
2. 检查候选是否满足硬约束；
3. 计算候选的规则调整分；
4. 选择调整分最高的物品；
5. 更新作者、类目、广告和配额状态；
6. 继续选择下一个位置。

伪代码：

```cpp
for (position = 0; position < top_k; ++position) {
    best = nullptr;

    for (candidate : remaining_candidates) {
        if (!satisfy_hard_rules(candidate, position, state)) {
            continue;
        }

        score = rank_score(candidate)
              + business_bonus(candidate, state)
              - repeat_penalty(candidate, state);

        best = max(best, candidate, score);
    }

    append(best);
    update_state(best);
}
```

优点：

- 可以同时处理多种规则；
- 规则判断与分数调整容易拆分；
- 容易解释和调试；
- 适合百量级候选；
- 可以自然加入降级逻辑。

缺点：

- 是局部贪心，不保证全局最优；
- 如果不做配额前瞻，可能在后面无法满足最低配额；
- 每增加一条规则都需要评估冲突关系。

本文最后的 C++ 示例采用这种方式。

---

## 4.4 方法四：约束优化

可以把最终排序建模为：

```text
最大化：
精排总收益 + 多样性收益 + 业务收益

约束：
广告数量、作者频次、类目窗口、固定位置、最低配额……
```

理论上可以使用：

- 整数规划；
- 动态规划；
- Beam Search；
- 约束搜索；
- 强化学习；
- Slate Optimization。

这种方案更接近全局优化，但在线成本和工程复杂度更高。

实际系统中通常会在：

```text
效果、延迟、稳定性、可解释性
```

之间做权衡，因此简单可控的贪心策略仍然非常常见。

# 5. 推荐的规则执行顺序

一个较清晰的重排管线如下：

```text
第一层：绝对过滤
    ↓
第二层：特殊内容预处理
    ↓
第三层：逐位置生成列表
    ↓
第四层：硬规则可行性检查
    ↓
第五层：软规则分数调整
    ↓
第六层：状态更新
    ↓
第七层：规则降级与兜底
    ↓
最终 Top-K
```

具体解释：

## 5.1 先执行硬过滤

先删除：

- 已看内容；
- 已下架内容；
- 风控内容；
- 无库存商品；
- 不满足地区要求的物品。

---

## 5.2 再处理必须固定的位置

例如：

```text
运营内容固定第 2 位
开屏广告固定第 1 位
活动卡片固定第 6 位
```

固定位置应尽早预留，否则普通候选可能占据这些位置。

---

## 5.3 逐位置选择普通候选

每个位置都重新计算：

```text
候选是否可放
候选当前的调整分
配额是否即将到期
```

注意：同一个候选在不同位置的分数可能不同。

例如广告：

```text
第 1 位：禁止
第 4 位：允许
第 6 位：如果上一条广告在第 4 位，则禁止
第 9 位：允许
```

---

## 5.4 更新列表状态

选择一个物品后，需要更新：

```text
作者计数
类目窗口
广告计数
最近广告位置
直播计数
最低配额完成情况
```

重排本质上是一个有状态的列表生成过程。

---

# 6. 规则冲突与降级机制

规则越多，越可能出现某个位置没有任何合法候选。

例如：

```text
前 3 位不能放广告
体育类目窗口已经达到上限
剩余自然内容全部是体育
新作者配额又即将到期
```

如果所有规则都绝对执行，系统可能无法填满列表。

因此，规则必须划分优先级。

## 6.1 推荐的优先级

```text
P0：安全、合规、不可用过滤
P1：商业总量、法律和产品强约束
P2：作者频控、广告间隔
P3：类目打散、多样性
P4：新鲜度、探索奖励等软目标
```

降级时从低优先级规则开始放宽：

```text
严格规则
    ↓ 无候选
放宽类目窗口
    ↓ 仍无候选
放宽局部打散
    ↓ 仍无候选
保留安全和商业硬约束，返回最高分候选
```

绝不能为了填满 Top-K 而放宽：

- 安全规则；
- 内容审核；
- 库存状态；
- 地域限制；
- 法律与合规限制。

# 7. 本文设计的业务规则集

下面设计一个短视频信息流 Top-10 重排规则集。

## 7.1 硬过滤

```text
R1：已看内容直接过滤
R2：不可用或已下架内容直接过滤
```

---

## 7.2 广告规则

```text
R3：前 3 位禁止广告
R4：Top-10 最多出现 2 条广告
R5：两条广告的位置差至少为 4
```

位置差至少为 4，例如：

```text
第 4 位广告
下一条广告最早出现在第 8 位
```

---

## 7.3 作者规则

```text
R6：同一作者最多出现 2 条
R7：同一作者不能连续出现
```

其中：

- R6 是全局频控；
- R7 是局部体验约束。

---

## 7.4 类目规则

```text
R8：最近 4 条中，同一类目最多出现 2 条
```

这不是限制整个 Top-10 最多有两条体育内容，而是避免局部集中。

例如下面是允许的：

```text
体育、科技、体育、影视、体育
```

因为滑动窗口不断向前移动。

---

## 7.5 直播规则

```text
R9：Top-5 最多出现 1 条直播
```

防止直播内容过多占据首屏。

---

## 7.6 新作者配额

```text
R10：Top-8 至少出现 1 条新作者内容
```

实现方式：

- 在前 8 位中为新作者增加软奖励；
- 如果到第 8 位仍未满足配额，则第 8 位强制选择新作者。

这体现了：

```text
软引导 + 截止位置硬保障
```

---

## 7.7 软分调整

候选物品的最终选择分数为：

```text
adjusted_score
=
rank_score
+ 0.05 × freshness
+ 新作者奖励
- 广告惩罚
- 类目重复惩罚
- 作者重复惩罚
```

具体规则：

```text
新鲜度奖励：0.05 × freshness
未完成新作者配额时，新作者加 0.08
广告扣 0.03
最近窗口中每有一个同类目物品，扣 0.025
同作者已经出现一次，再扣 0.03
```

这些系数仅用于演示。真实系统需要通过离线评估和 A/B 实验调节。

# 8. C++17 完整实现

下面代码实现：

- 硬过滤；
- 逐位置贪心选取；
- 广告位置与间隔约束；
- 作者频控；
- 类目滑动窗口；
- 新作者最低配额；
- 直播首屏限制；
- 软分调整；
- 三级规则降级；
- 输出最终物品顺序。

```cpp
#include <algorithm>
#include <cmath>
#include <iomanip>
#include <iostream>
#include <limits>
#include <optional>
#include <string>
#include <unordered_map>
#include <vector>

enum class ItemType { Organic, Ad, Live };

struct Item {
    int id;
    std::string title;
    std::string category;
    std::string author;
    ItemType type;
    double rank_score;
    double freshness;
    bool available;
    bool seen;
    bool new_creator;
};

struct RuleSet {
    std::size_t top_k = 10;
    std::size_t no_ad_before = 3;           // 前 3 位禁止广告
    std::size_t max_ads_in_top_k = 2;       // Top-K 最多 2 条广告
    std::size_t min_ad_position_gap = 4;    // 两条广告的位置差至少为 4
    std::size_t max_same_author = 2;        // 同一作者最多 2 条
    std::size_t category_window = 4;        // 最近 4 个位置
    std::size_t max_same_category_in_window = 2;
    std::size_t new_creator_deadline = 8;   // Top-8 至少 1 条新作者内容
    std::size_t max_live_in_top5 = 1;
};

struct State {
    std::vector<const Item*> selected;
    std::unordered_map<std::string, int> author_count;
    int ad_count = 0;
    int live_count_top5 = 0;
    bool has_new_creator = false;
    std::optional<std::size_t> last_ad_position;
};

static bool is_ad(const Item& item) {
    return item.type == ItemType::Ad;
}

static bool is_live(const Item& item) {
    return item.type == ItemType::Live;
}

static int category_count_in_window(
    const State& state,
    const std::string& category,
    std::size_t window_size)
{
    const std::size_t begin =
        state.selected.size() > window_size
            ? state.selected.size() - window_size
            : 0;

    int count = 0;
    for (std::size_t i = begin; i < state.selected.size(); ++i) {
        if (state.selected[i]->category == category) {
            ++count;
        }
    }
    return count;
}

static bool must_choose_new_creator(
    const State& state,
    std::size_t position,
    const RuleSet& rules)
{
    // position 使用 0-based。若即将填充 Top-8 的最后一个位置且尚无新作者，
    // 则该位置必须选择新作者内容。
    return !state.has_new_creator
        && position + 1 == rules.new_creator_deadline;
}

static bool can_place(
    const Item& item,
    const State& state,
    std::size_t position,
    const RuleSet& rules,
    int relax_level)
{
    // 绝对硬约束：广告位置与广告总量。
    if (is_ad(item)) {
        if (position < rules.no_ad_before) {
            return false;
        }
        if (state.ad_count >= static_cast<int>(rules.max_ads_in_top_k)) {
            return false;
        }
        if (state.last_ad_position.has_value()
            && position - *state.last_ad_position < rules.min_ad_position_gap) {
            return false;
        }
    }

    // Top-8 至少有一个新作者内容。
    if (must_choose_new_creator(state, position, rules)
        && !item.new_creator) {
        return false;
    }

    // Top-5 最多一条直播。
    if (position < 5 && is_live(item)
        && state.live_count_top5 >= static_cast<int>(rules.max_live_in_top5)) {
        return false;
    }

    // 同一作者最多两条：即使降级也保留。
    auto author_it = state.author_count.find(item.author);
    if (author_it != state.author_count.end()
        && author_it->second >= static_cast<int>(rules.max_same_author)) {
        return false;
    }

    if (relax_level == 0) {
        // 严格模式：同一作者不能连续出现。
        if (!state.selected.empty()
            && state.selected.back()->author == item.author) {
            return false;
        }

        // 严格模式：最近 4 条中，同类目最多 2 条。
        if (category_count_in_window(
                state, item.category, rules.category_window)
            >= static_cast<int>(rules.max_same_category_in_window)) {
            return false;
        }
    } else if (relax_level == 1) {
        // 一级降级：允许类目窗口超限，但仍禁止作者连续出现。
        if (!state.selected.empty()
            && state.selected.back()->author == item.author) {
            return false;
        }
    }

    // relax_level == 2 时，仅保留绝对硬约束和作者总频控。
    return true;
}

static double adjusted_score(
    const Item& item,
    const State& state,
    std::size_t position,
    const RuleSet& rules)
{
    double score = item.rank_score;

    // 新鲜度奖励。
    score += 0.05 * item.freshness;

    // 在新作者配额尚未满足，且仍处于配额窗口内时给予奖励。
    if (!state.has_new_creator
        && position < rules.new_creator_deadline
        && item.new_creator) {
        score += 0.08;
    }

    // 广告轻微降权，避免广告仅靠较高基础分占据过前位置。
    if (is_ad(item)) {
        score -= 0.03;
    }

    // 局部重复软惩罚。硬约束负责“不能超过”，软分负责“尽量分散”。
    const int category_count = category_count_in_window(
        state, item.category, rules.category_window);
    score -= 0.025 * category_count;

    auto author_it = state.author_count.find(item.author);
    if (author_it != state.author_count.end()) {
        score -= 0.03 * author_it->second;
    }

    return score;
}

static void update_state(State& state, const Item& item, std::size_t position) {
    state.selected.push_back(&item);
    ++state.author_count[item.author];

    if (is_ad(item)) {
        ++state.ad_count;
        state.last_ad_position = position;
    }
    if (position < 5 && is_live(item)) {
        ++state.live_count_top5;
    }
    if (item.new_creator) {
        state.has_new_creator = true;
    }
}

static std::vector<const Item*> rerank_with_rules(
    const std::vector<Item>& candidates,
    const RuleSet& rules)
{
    // 第一步：硬过滤。真实系统中通常还会加入风控、地域、库存等检查。
    std::vector<const Item*> pool;
    for (const auto& item : candidates) {
        if (item.available && !item.seen) {
            pool.push_back(&item);
        }
    }

    std::vector<bool> used(pool.size(), false);
    State state;

    for (std::size_t position = 0;
         position < rules.top_k && state.selected.size() < pool.size();
         ++position)
    {
        int best_index = -1;
        double best_score = -std::numeric_limits<double>::infinity();
        int selected_relax_level = -1;

        // 逐级降级：严格规则 -> 放宽类目窗口 -> 放宽局部打散。
        for (int relax_level = 0; relax_level <= 2; ++relax_level) {
            best_index = -1;
            best_score = -std::numeric_limits<double>::infinity();

            for (std::size_t i = 0; i < pool.size(); ++i) {
                if (used[i]) {
                    continue;
                }

                const Item& item = *pool[i];
                if (!can_place(item, state, position, rules, relax_level)) {
                    continue;
                }

                const double score = adjusted_score(
                    item, state, position, rules);

                if (score > best_score) {
                    best_score = score;
                    best_index = static_cast<int>(i);
                }
            }

            if (best_index != -1) {
                selected_relax_level = relax_level;
                break;
            }
        }

        if (best_index == -1) {
            std::cerr << "No feasible candidate for position "
                      << position + 1 << '\n';
            break;
        }

        used[best_index] = true;
        update_state(state, *pool[best_index], position);

        std::cout << "position=" << position + 1
                  << ", relax_level=" << selected_relax_level
                  << ", adjusted_score=" << std::fixed
                  << std::setprecision(3) << best_score << '\n';
    }

    return state.selected;
}

}
```

# 10. 代码结构如何理解？

## 10.1 `RuleSet`

```cpp
struct RuleSet
```

保存所有可配置规则。

真实系统中，这些参数通常不会写死在代码中，而会来自：

- 配置中心；
- 实验平台；
- 动态策略配置；
- 不同用户分群的实验参数。

例如：

```text
实验组 A：广告间隔为 4
实验组 B：广告间隔为 5
实验组 C：Top-10 最多 1 条广告
```

---

## 10.2 `State`

```cpp
struct State
```

保存当前列表生成状态：

```text
已经选出的物品
每个作者出现次数
当前广告数量
Top-5 直播数量
是否已包含新作者
上一条广告位置
```

这说明重排不是无状态排序，而是：

```text
选一个物品
    ↓
更新状态
    ↓
状态影响下一次选择
```

---

## 10.3 `can_place`

```cpp
bool can_place(...)
```

负责检查硬约束。

它只回答：

```text
当前候选能不能放在这个位置？
```

而不回答候选之间谁更好。

将可行性判断与分数计算分离，可以避免把所有逻辑塞进一个复杂公式。

---

## 10.4 `adjusted_score`

```cpp
double adjusted_score(...)
```

负责软规则加减分。

它回答：

```text
在所有可以放置的候选中，当前应该优先选择谁？
```

基础仍然是精排分数：

```cpp
double score = item.rank_score;
```

业务规则只在精排分数基础上调整，而不是完全抛弃模型结果。

---

## 10.5 `relax_level`

程序实现三个等级：

```text
Level 0：
执行全部规则

Level 1：
放宽类目滑动窗口
仍禁止作者连续出现

Level 2：
进一步放宽局部打散
保留广告硬约束和作者总频控
```

这种实现能够保证：

- 正常情况下严格遵守规则；
- 候选不足时尽量填满列表；
- 核心硬约束始终保留；
- 每次降级都有日志可观察。

# 11. 工业实现还需要补充什么？

示例代码用于理解完整流程，但真实在线系统还需要以下能力。

## 11.1 规则配置化

不要把规则写死：

```cpp
if (position < 3)
```

更适合：

```cpp
if (position < config.no_ad_before)
```

配置还应带有：

- 规则 ID；
- 规则版本；
- 实验组；
- 生效时间；
- 业务线；
- 用户分群；
- 降级优先级。

---

## 11.2 规则组件化

可以设计统一接口：

```cpp
class Rule {
public:
    virtual ~Rule() = default;

    virtual bool allow(
        const Item& item,
        std::size_t position,
        const Context& context) const = 0;

    virtual double score_delta(
        const Item& item,
        std::size_t position,
        const Context& context) const {
        return 0.0;
    }
};
```

不同规则分别实现：

```text
AdPositionRule
AuthorFrequencyRule
CategoryWindowRule
NewCreatorQuotaRule
FreshnessBonusRule
```

优点：

- 规则可插拔；
- 易于单元测试；
- 便于实验；
- 规则职责清晰。

但也要避免过度面向对象导致在线调用开销和代码复杂度增加。高性能系统可以使用：

- 静态多态；
- 函数对象；
- 枚举分发；
- 批量规则执行；
- 预编译规则计划。

---

## 11.3 规则冲突检测

例如同时配置：

```text
Top-5 禁止直播
Top-5 至少出现 1 条直播
```

这是直接冲突。

配置发布前应该检查：

- 上限是否小于下限；
- 固定位置是否重复；
- 配额是否超过 Top-K；
- 间隔要求是否使配额不可完成；
- 候选池是否可能满足最低配额。

---

## 11.4 配额前瞻

本文只对一个新作者配额设置截止位置。

如果有多个最低配额：

```text
Top-10 至少 1 条新作者
Top-10 至少 2 条本地内容
Top-10 至少 1 条直播
```

只在最后位置强制选择可能已经来不及。

需要检查：

```text
剩余位置数
是否足以完成所有尚未满足的最低配额
```

例如：

```cpp
if (remaining_slots == missing_quota_count) {
    // 后续位置只能选择能够完成配额的物品
}
```

更复杂时可以使用：

- Beam Search；
- 回溯搜索；
- 小规模动态规划；
- 约束求解。

---

## 11.5 超时与兜底

在线重排必须有延迟预算。

常见降级链路：

```text
复杂规则重排
    ↓ 超时
简化规则重排
    ↓ 超时
仅执行硬过滤和广告规则
    ↓ 异常
返回精排 Top-K
```

推荐服务的首要目标是：

```text
按时返回一个合法结果
```

而不是为了获得理论最优顺序导致请求超时。

## 11.6 可解释日志

每个物品为什么被提前或后移，最好能记录原因：

```text

base_score=0.82
freshness_bonus=0.05
new_creator_bonus=0.08
category_penalty=0
final_score=0.95
selected_position=5
```

被拒绝的候选也可以记录采样日志：

```text

reason=no_ad_before_top3
```

这对于：

- 线上问题排查；
- 产品规则验证；
- A/B 实验分析；
- 配置错误发现；
- 推荐结果解释

非常重要。

# 12. 复杂度分析

设：

```text
候选数量为 N
最终展示数量为 K
```

逐位置贪心每次遍历所有剩余候选，复杂度约为：

```text
O(N × K)
```

对于：

```text
N = 200
K = 20
```

只需要大约数千次规则判断，通常适合在线服务。

但规则检查内部不应每次扫描整个历史列表。

例如：

- 作者总次数使用哈希表；
- 广告间隔保存最后位置；
- 类目窗口只扫描固定大小窗口；
- 最低配额使用计数器；
- 最近内容使用 `deque` 或环形队列。

避免把复杂度退化为：

```text
O(N × K²)
```

# 14. 总结

业务规则约束下的重排，本质上是：

```text
在精排相关性的基础上，
逐位置构造一个满足安全、商业、体验和生态规则的最终列表。
```

需要记住以下几点：

1. **硬过滤先执行**：已下架、已看、无库存等物品不能进入候选池。
2. **硬约束与软约束分开**：`can_place` 决定能否放置，`adjusted_score` 决定优先级。
3. **重排是有状态的**：每选一个物品，都要更新作者、类目、广告、直播和配额状态。
4. **最低配额需要前瞻**：不能只处理上限规则，还要保证后续有足够位置完成配额。
5. **规则必须有优先级**：无候选时从低优先级多样性规则开始降级。
6. **安全规则不能降级**：任何情况下都不能为了填满列表绕过审核、库存或合规约束。
7. **工业上常用逐位置贪心**：实现清晰、延迟可控，适合百量级候选生成 Top-K。
8. **最终目标不是规则越多越好**：而是在相关性、用户体验、商业收益和内容生态之间取得平衡。

可以用一句话概括：

> 精排给出“物品价值”，业务规则重排负责把这些物品组织成一个真正可以展示的列表。
